# M45 成員星判定：方法與結論

資料：Gaia DR3，M45 中心 5° 錐形，G < 18，視差 > 4 mas，共 6,956 顆
工具：pyUPMASK（Pera et al. 2021），對照 Hunt & Reffert 2023（以下簡稱 HR23）
狀態：第 1 步（成員判定）已跑通並做過穩健性檢驗；第 2–5 步見
`docs/planning/PDMF_TO_IMF_PLAN.md`。方法演進與已推翻結論見
[CHANGELOG.md](../../CHANGELOG.md)。

## 一、結論

**成員名單**：門檻 P ≥ 0.7 下選出約 1,297 顆。這個門檻不是最佳化任何
指標得來的，是從機率分布的穩定結構決定的——0.5–0.9 是各種設定
（PCA 開關、投影修正、誤差重抽方式、亂數種子）之間的成員數穩定谷地
（1,292–1,306 顆，離散度 1.1–1.7%），0.95 開始崩（種子間離散度衝到
9.2%，0.99 更到 48%）。取 0.7 是落在自己這份分布穩定谷地的正中間，
與外部目錄無關——Cantat-Gaudin 用的 0.7 只是數值恰好相同，兩者機率
構造不同（pyUPMASK 是 KDE 概似比後驗，會在成員分布核心飽和到接近 1；
原始 UPMASK 是重抽頻率，上限被輪數綁住），不可通約，不能沿用。

**與 HR23 的關係**：

| | 顆數 |
|---|---|
| HR23 給 M45 的全天成員 | 1,721 |
| 落在 5° 錐內 | 1,595（92.7%） |
| 錐內且 G < 18 | 1,369 |
| 其中 Prob ≥ 0.5 | 930 |
| **我抓到的** | **930（全中）** |
| 我判為成員但 HR23 Prob < 0.5 | 258 |
| └ 其中 HR23 仍收在成員表 | 238（Prob 中位 0.436） |
| └ HR23 完全沒收 | **20** |

真正的判斷分歧只有 20 顆，佔 1.7%。這 20 顆的自行運動與視差跟公認
成員無法區分，不在 HR23 的 `membrej`（剔除候選）表裡，也沒被指派給
任何其他星團——它們在天球外圍的佔比遞增（3–4° 處達 6.7%），符合
密度式演算法在低密度外圍失效的預期。

recall = 1.000（930 顆 HR23 成員全部拿到 ≥ 0.9963 的機率）在每個門檻
都飽和，只證明 M45 是簡單題（|pm| ≈ 50 mas/yr，離場星中心一個數量級），
本身沒有鑑別力。precision 0.783 是低估——那 258 顆「誤判」裡 92% HR23
其實也收在成員表，只是 Prob < 0.5，兩邊都認為它們可能是成員，差別在
信心值的刻度。

**穩健性**：科學結論（成員名單、930/20 的分歧結構）對所有測過的設定
不敏感；只有機率門檻的精確位置在 P ≥ 0.95 之後敏感，原因是機率在
0.999 附近高度堆積（0.999–1.0 擠了 1,092 顆），門檻卡在密度堆山腳，
任何微小的數值移動都會讓大量星整批跨過門檻。

**最重要的限制**：跟 HR23 一致**不構成驗證**。兩邊用同一份 Gaia DR3，
不是獨立測量；一致只說明兩套演算法在同一份資料上收斂到相近的解。
真正的獨立驗證需要天測以外的證據（徑向速度、鋰吸收線、自轉週期、
光譜金屬豐度）。正確的框架是「比較」，有價值的產出是那 20 顆爭議星，
不是一致率。

## 二、資料取得與前處理

資料透過既有的 Gaia 匯出工具（TAP 協定）取得；M45 5° + G<18 的查詢
資料量大，同步端點會逾時（HTTP 408），已加非同步 UWS fallback（含
連續 5 次失敗才放棄的輪詢容錯）。落地 CSV 反推的星團參數
（pm = (+19.94, −45.39) mas/yr、視差 7.366 mas → 135.8 pc）與文獻值
一致。

前處理三道切法的量測結果：

| 條件 | 剩餘星數 |
|---|---|
| 5° 全部 | 718,270 |
| + G < 18 | 198,672 |
| + 視差 > 4 | 6,956 |

視差切在 HR23 成員裡誤殺 0 顆（`Plx < 4` 與 `Plx < 5` 皆是），但清掉
97% 的汙染星——這一刀不偏誤成員判定，但也代表不能宣稱是 pyUPMASK
把成員分辨出來的，樣本本身已經先被大幅淨化。`RUWE < 1.4` 不能當
品質切：會砍掉 HR23 成員裡 168 顆（12%），RUWE 高的主因是未解析
雙星，M45 年輕、雙星比例高，這一刀會系統性移除真成員。座標處理用
gnomonic 切平面投影而非直接餵 RA/Dec——dec = 24° 處 RA 一度只有約
0.91 天球度，直接餵會讓天區橫向拉伸，影響 pyUPMASK 用 Ripley's K
做的空間集中度檢定。

光度沒有參與分群，判定為成員的星在色光圖上落成一條乾淨的主序帶，
是唯一不依賴 Gaia 天測的獨立檢查，通過。

## 三、pyUPMASK 使用上的實務問題

- `modules/dataIO.py` 原本 `from distutils.util import strtobool`，
  distutils 在 Python 3.12 被移除（本機為 3.14），已補等效實作。
- `params.ini` 從當前工作目錄讀取，必須在 pyUPMASK 目錄下執行。
- `input/` 底下所有非 `.md` 檔都會被當成輸入，每次只能放一個。
- `resampleFlag` 預設 **False**，等於完全不使用測量誤差，必須手動
  開啟。
- `modules/outer.py` 的誤差重抽每顆星只抽一個亂數套用到三個維度，
  各維擾動完全相關；已做成 `PYUPMASK_INDEP_RESAMPLE=1` 環境變數開關，
  改成獨立抽樣只造成 1.3% 差異，在此資料集上不重要。
- 輸出 `probs_final = -1` 代表被離群遮罩，不是機率，統計時要排除。
- 可重現性所需的完整設定：`PCAflag`/`PCAdims`、`N_membs`、`OL_runs`、
  `clust_method`、離群遮罩方法與門檻、亂數種子。只寫「使用 pyUPMASK」
  不足以重現。
