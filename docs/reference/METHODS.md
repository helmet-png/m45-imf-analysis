# M45 成員星判定：方法、嘗試與修正記錄

資料：Gaia DR3，M45 中心 5° 錐形，G < 18，視差 > 4 mas，共 6,956 顆
工具：pyUPMASK（Pera et al. 2021），對照 Hunt & Reffert 2023（以下簡稱 HR23）
狀態：第 1 步（成員判定）已跑通並做過穩健性檢驗；第 2–5 步未開始

---

## 一、目前的結論

**成員名單**：門檻 P ≥ 0.7 下選出約 1,297 顆。這個門檻不是最佳化任何指標得來的，
是從機率分布的穩定結構決定的（見第五節）。

**與 HR23 的關係**：

| | 顆數 |
|---|---|
| HR23 給 M45 的全天成員 | 1,721 |
| 落在 5° 錐內 | 1,595（92.7%） |
| 錐內且 G < 18 | 1,369 |
| 其中 Prob ≥ 0.5 | 930 |
| **我抓到的** | **930（全中）** |
| 我判為成員但 HR23 Prob < 0.5 | 258 |
| └ 其中 HR23 仍收在成員表 | 238（Prob 中位 0.436） |
| └ HR23 完全沒收 | **20** |

真正的判斷分歧只有 20 顆，佔 1.7%。這 20 顆的自行運動與視差跟公認成員無法區分，
而且不在 HR23 的 `membrej`（剔除候選）表裡，也沒被指派給任何其他星團 ——
HR23 的流程從頭到尾沒把它們當成候選。它們在天球外圍的佔比遞增（3–4° 處達 6.7%），
符合密度式演算法（HDBSCAN）在低密度外圍失效的預期。

**穩健性**：成員判定對所有測過的設定都不敏感。投影修正、誤差重抽方式、PCA 開關、
亂數種子，在 P ≥ 0.7 下的成員數全部落在 1,292–1,306，且都抓到完全相同的 930 顆。

**最重要的限制**：跟 HR23 一致**不構成驗證**。兩邊用同一份 Gaia DR3，不是獨立測量；
一致只說明兩套演算法在同一份資料上收斂到相近的解。真正的獨立驗證需要天測以外的
證據（徑向速度、鋰吸收線、自轉週期、光譜金屬豐度）。因此正確的框架是「比較」，
有價值的產出是那 20 顆爭議星，不是一致率。

## 二、資料取得

**問題**：既有的 Gaia 匯出工具走 TAP 同步端點。M45 5° 加 G<18 的查詢會掃過大量資料列，
超過同步端點時限，ESA 直接回 HTTP 408。

**判斷**：不重寫抓取層。既有工具已經有名稱解析、欄位選擇、全部抓取等功能，
缺的只是一條非同步路徑。

**作法**：在既有 `run_tap_query` 上加 fallback —— 先試同步，遇 408 或讀取逾時才轉
UWS 非同步 job。前端、API 介面、打包指令都不動。

**驗證**：不只確認新路徑會回傳，還確認同一個查詢走同步**仍然** 408（證明 fallback 不是
安慰劑），以及原本就能過的查詢沒有被拖慢。最後從落地的 CSV 反推星團參數：
pm = (+19.94, −45.39) mas/yr、視差 7.366 mas → 135.8 pc，與文獻值一致。

後續在輪詢中被 ESA 斷線一次，因此又補上輪詢容錯（連續 5 次失敗才放棄）。

## 三、前處理與循環性檢驗

**核心疑慮**：先用視差把資料切過一輪，是不是等於預先決定了誰是成員？

**判斷**：把這個疑慮轉成可量測的宣稱，而不是用論述回答。

**量測結果**：

| 條件 | 剩餘星數 |
|---|---|
| 5° 全部 | 718,270 |
| + G < 18 | 198,672 |
| + 視差 > 4 | 6,956 |

而 HR23 的成員裡，被 `Plx < 4` 誤殺的是 **0 顆**，被 `Plx < 5` 誤殺的也是 0 顆。

**結論分兩句，兩句都要寫進論文**：這一刀不會偏誤成員判定（它不誤殺成員、也不定義
團心位置）；但它清掉了 97% 的汙染星，所以不能宣稱是 pyUPMASK 把成員分辨出來的。

**附帶發現**：`RUWE < 1.4` 會砍掉 HR23 成員裡的 168 顆（12%）。RUWE 高的主因是未解析
雙星，而 M45 年輕、雙星比例高 —— 這一刀會系統性且有偏地移除真成員。當雙星指標可以，
當品質切不行。

**座標處理**：用 gnomonic 切平面投影而非直接餵 RA/Dec。在 dec = 24° 處 RA 一度只有
約 0.91 天球度，直接餵會讓天區橫向拉伸，影響 pyUPMASK 用 Ripley's K 做的空間集中度檢定。

## 四、首次跑通與結果拆解

25 輪外圈 + 誤差重抽，6,956 顆跑 9.8 分鐘。

**recall = 1.000 在所有門檻**。先當成可疑訊號查證：930 顆 HR23 成員拿到的機率最低是
0.9963、中位 0.9999，確實全部命中。是真的，但**沒有資訊量** —— 這個指標在每個門檻都
飽和，只證明 M45 是簡單題（|pm| ≈ 50 mas/yr，離場星中心一個數量級）。

**precision 0.783 是低估**。拆解那 258 顆「誤判」後發現 238 顆（92%）HR23 其實也收在
成員表，只是 Prob < 0.5。兩邊都認為它們可能是成員，差別在信心值的刻度。

**獨立旁證**：光度完全沒有參與分群，但判定為成員的星在色光圖上落成一條乾淨的主序帶。
這是唯一不依賴 Gaia 天測的檢查，通過。

## 五、穩健性檢驗（本專案最重要的一段）

這一段推翻了前一段建立的幾個結論，過程值得完整記錄。

**第一輪：測設定的影響**。在 P ≥ 0.99（當時因為它對 HR23 的 F1 最高而選用）下得到：
PCA 開關差 36.1%、投影修正差 3.5%、重抽方式差 1.3%。當時的結論是「PCA 是最關鍵的設定」。

**第二輪：測雜訊底線**。意識到沒有雜訊底線就無法宣稱任何效應是真的，於是同資料、
同設定，只換亂數種子跑三次。結果種子 42 → 43 的差異是 **31.7%**，跟 PCA 效應同量級。
第一輪的三個數字全部埋在雜訊裡，不成立。

**第三輪：診斷**。查各門檻下的成員數，發現不穩定完全集中在尾巴：

| 門檻 | seed42 | seed43 | seed44 | seed99 | 離散度 |
|---|---|---|---|---|---|
| P ≥ 0.5 | 1,318 | 1,321 | 1,325 | 1,311 | 1.1% |
| P ≥ 0.7 | 1,297 | 1,303 | 1,306 | 1,292 | 1.1% |
| P ≥ 0.9 | 1,264 | 1,255 | 1,270 | 1,249 | 1.7% |
| P ≥ 0.95 | 1,237 | 1,133 | 1,250 | 1,217 | 9.2% |
| P ≥ 0.99 | 1,188 | **815** | 1,208 | 1,175 | **48%** |

在 P ≥ 0.5，七組變因（含 PCA 開關）全部落在 1,302–1,325，且抓到完全相同的 930 顆
HR23 成員。**科學結論對所有旋鈕都不敏感；只有門檻位置敏感。**

**第四輪：根因**。機率分布的細部結構顯示，0.5–0.7 之間只有約 20 顆星、0.7–0.9 只有
33–48 顆，但 0.999–1.0 擠了 1,092 顆。0.99 這個門檻正好卡在密度堆的山腳。
seed43 並不是「找到比較少成員」，而是把約 400 顆星的機率從 ≥0.999 小幅下推到
0.9–0.98 —— 那些星沒有變成非成員，只是數值移動了幾個百分點，但門檻卡在山腳，
小幅移動就整批跨過去。

**第五輪：為什麼會堆在 0.999**。讀 `modules/KDEAnalysis.py` 發現 pyUPMASK 的機率是
`1/(1 + L_field/L_memb)` —— 兩個核密度估計的概似比後驗。對深在成員分布核心的星，
概似比接近零、後驗飽和到 1。**這個堆積反映的是「星團跟場星分得多開」，不是
「對成員身分多有把握」。** 在飽和區裡 P = 0.9999 與 0.999 沒有意義上的差別。

## 六、門檻的正當性

原始 UPMASK（Cantat-Gaudin & Anders 2020 使用）的機率是**該星在多少比例的輪次中被判為
成員**，一個頻率，上限被輪數綁住。pyUPMASK 的機率是**KDE 概似比後驗的多輪平均**，
會飽和。兩者都叫成員機率、都在 [0,1]，但是不同的數學構造，**數值不可通約**。

因此 Cantat-Gaudin 用的 0.7 不能直接搬過來。門檻必須由自身分布的結構決定：
從上表看，0.5–0.9 是穩定谷地，0.95 開始崩。**取 0.7，理由是它落在自己這份分布的
穩定谷地正中間**，與外部目錄無關。

與前人比對時，因為刻度不可通約，不能對齊門檻。可行作法是比成員名單的集合重疊
（現行作法），或取雙方機率排序前 N 名比重合度（尚未做）。

## 七、已知的錯誤與更正

過程中做過的錯誤判斷，逐條記錄：

1. **汙染率估計**：估「切完仍有九成九汙染」，實測 81%。使用者的直覺較準。
2. **recall 天花板**：用 `Nt/N` 推出 59%，但 `Nt` 是三維判準不是角距判準；實測 5° 錐內
   有 1,595 顆成員，天花板是 92.7%。
3. **RUWE < 1.4**：一度列為品質切，實測會砍掉 12% 的真成員，撤回。
4. **投影效應量級**：宣稱是內部彌散的 5.2 倍，但那是拿「跨天區極差」比「標準差」，
   不對等。實測投影對散布的貢獻約 0.62 mas/yr，與內部彌散 0.78 同量級。
5. **「PCA 是最關鍵設定」**：36% 是 0.99 門檻造成的假象，在 P ≥ 0.5 只差 2.3%。
6. **未量雜訊底線就報效應**：報了三個差異數字，之後才發現它們低於種子間變異。
7. **拿 F1 對 HR23 挑門檻**：等於用對照目錄調自己的超參數，且挑到了方法最脆弱的點。
8. **「可與 Cantat-Gaudin 直接比較」**：兩者機率構造不同，數值不可通約。

第 5 至 8 項有共同的根源：在建立雜訊底線之前就開始解讀差異。

## 八、pyUPMASK 使用上的實務問題

- `modules/dataIO.py` 原本 `from distutils.util import strtobool`，distutils 在 Python 3.12
  被移除（本機為 3.14），已補等效實作
- `params.ini` 從當前工作目錄讀取，必須在 pyUPMASK 目錄下執行
- `input/` 底下所有非 `.md` 檔都會被當成輸入，每次只能放一個
- `resampleFlag` 預設 False，等於完全不使用測量誤差
- `modules/outer.py` 的誤差重抽每顆星只抽一個亂數套用到三個維度，各維擾動完全相關。
  已做成 `PYUPMASK_INDEP_RESAMPLE=1` 環境變數開關；實測改成獨立抽樣只造成 1.3% 差異，
  在此資料集上不重要
- 輸出 `probs_final = -1` 代表被離群遮罩，不是機率，統計時要排除
- 可重現性所需的完整設定：`PCAflag`/`PCAdims`、`N_membs`、`OL_runs`、`clust_method`、
  離群遮罩方法與門檻、亂數種子。只寫「使用 pyUPMASK」不足以重現
