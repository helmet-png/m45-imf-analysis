## 第 0 節：三分鐘摘要（趕時間先看這裡）

**問題**：星團的初始質量函數（IMF）描述「星團剛形成時，不同質量的恆星
各誕生了多少顆」，通常寫成冪律 ξ(m) ∝ m^(−α)。我們用兩種完全獨立的方法
去測 M45（昴宿星團）的 α：**傳統法**（每顆星當單星、查等時線指派質量、
對質量做冪律擬合）與**前向模型**（把雙星、消光、選擇函數都放進同一個
統計模型裡聯合擬合）。

**用詞澄清（讀者/教授容易當場問到，先講清楚）**：我們**實際量到的是
現時質量函數（PDMF, present-day mass function）**——現在還留在星團裡、
通過我們測光篩選的這 1,078 顆星的質量分布，不是星團剛形成時的分布。
PDMF 要能代表 IMF，前提是星團形成之後**質量分層／動力學演化**沒有把
重星跟輕星的空間分布明顯拉開（重星傾向沉到核心、輕星傾向被甩到外圍）。

**這個前提目前有一個直接的反面訊號，不是純理論擔心**：我們把樣本按
角距離切成四個環帶重新各自擬合 α（見《docs/reports/報告_完整說明.md》1.4 節），結果
α 隨半徑單調上升（0–1° 是 1.77±0.11，3–5.1° 是 2.29±0.21），質量中位數
單調下降，跟質量分層的預期方向一致，是全專案最穩固的結果之一（同一套
方法在不同環帶上比較，系統誤差大致抵消）。**這證明質量分層在 M45 裡
確實存在**，不是「理論上可能但沒發生」。但這個測試回答的是「取樣範圍
*內部*的相對結構」，沒有回答「我們的 5.1° 取樣範圍夠不夠大，有沒有
漏掉已經被甩到範圍外、甚至已經脫離星團的輕星」——後者才是把「PDMF
（我們量到的）」換算成「IMF（星團剛形成時的）」真正缺的那一塊，
目前完全沒有量化。這件事已被列為論文用詞必須訂正的項目（見
`LIMITATIONS.md`／`PAPER_OUTLINE.md` 的 A 類清單「PDMF ≠ IMF」）。
下文為了跟一般讀者的先備知識銜接，行文仍沿用「IMF」「α」這些字樣，
但嚴格說每一處都該讀成「PDMF（是否等於 IMF 仍待確認，且已有分層訊號）」。

**這份文件在做的事**：傳統法內部有好幾種處理未解析雙星的方式（忽略、
用色光圖剔除、用天測品質剔除、用官方目錄剔除、用文獻修正量），我們把
五種都做過一輪，同時用前向模型生成「已知答案的假資料」去校準每一種
方法的真實誤差棒（因為傳統統計學教科書給的誤差棒被證明低估了 4 倍）。

**結果**：

| 變體 | 真實資料 α | 誤差 |
|---|---|---|
| 全當單星 | 2.395 | ±0.118 |
| CMD 剔除 | 2.371 | ±0.121 |
| RUWE 剔除 | 2.395 | ±0.119 |
| GaiaNSS 剔除 | 2.423 | ±0.112 |

五種傳統變體全部落在 2.37–2.42，彼此差距遠小於各自的統計誤差，而且
跟完全獨立的前向模型高度吻合。**選擇哪一種雙星處理方式，對 M45 這批
資料的最終答案幾乎不影響**——這本身就是一個值得報告的結論。

## 第一節：暖身——這一切在算什麼

### 1.1 星團與質量函數

一個星團誕生時，不同質量的恆星數量不是隨機的：輕的恆星（像太陽或更輕）
誕生得多，重的恆星（好幾倍太陽質量）誕生得少，而且這個「多多少」的
關係在很寬的質量範圍裡大致是一條**冪律**：

    ξ(m) dm = 質量落在 [m, m+dm] 之間的恆星數量
    ξ(m) ∝ m^(−α)

α 越大，代表質量分布越陡（重星相對輕星少得更快）；α 越小，代表分布
越平。Salpeter（1955）量太陽附近的恆星，得到 α ≈ 2.35，這是最常被
引用的標竿值，也是這份文件後面「假資料真值」取 2.35 的原因。

**為什麼會是冪律**：如果你把星數對質量畫在**雙對數座標**（x 軸 log m、
y 軸 log ξ）上，冪律會變成一條**直線**：

    ξ(m) = A · m^(−α)
    log ξ(m) = log A − α · log m

這是判斷「這是不是冪律」的標準做法——真實觀測資料在雙對數座標上如果
大致是直線，α 就是那條直線的斜率（取負號）。這也是為什麼我們的目標
量叫「斜率」。

### 1.2 問題：太空中沒有磅秤

我們沒辦法把星星抓下來秤重，能量到的只有兩件事：

1. **視星等（apparent magnitude）**：這顆星看起來多亮，用對數刻度表示：
   `m = −2.5 · log₁₀(F) + 常數`，F 是接收到的光通量。星等**越小越亮**
   （這是天文學的歷史包袱，早期用眼睛分等級，最亮的星定義成 1 等）。
2. **顏色（color）**：同一顆星在不同波段（例如藍色 BP 與紅色 RP）的
   星等差，`顏色 = BP − RP`。顏色越大代表星越紅（越冷）。

**恆星物理學告訴我們**（這部分是既有的恆星結構理論，這裡不重新推導，
只用結論）：對於還在「主序」階段（穩定燃燒氫的階段，恆星一生中最長
的階段）的恆星，質量越大，表面溫度越高（越藍）、也越亮。這個「質量
→ 亮度、顏色」的對應關係，對一群**同年齡、同金屬量**的恆星畫出來，
會是色光圖（CMD：顏色-星等圖）上的一條曲線，叫做**等時線**
（isochrone，字面意思是「相同時間」——同一條線上的每一點都對應同一個
年齡）。

**關鍵想法**：如果我們已經知道 M45 的年齡、離我們多遠（決定視星等要
扣掉多少）、被多少星際塵埃擋光（消光），我們就能算出一條理論等時線：
每個質量對應一個理論視星等 G 與顏色。**反過來**，只要觀測到一顆星的
G 星等，我們就能在這條曲線上找到「大約是這個星等的地方，質量是多少」
——這就是傳統法的核心招式，稱為「質量指派」（mass assignment）。

## 第二節：傳統法五步驟總覽

先看全貌，再一步步拆解：

```
觀測資料（1,078 顆星的顏色、星等、天測品質、官方雙星目錄旗標）
        │
        ▼
選一條等時線（用當下已知最佳的年齡、消光、金屬量）
        │
        ▼
【可選，五選一或不做】剔除疑似雙星（CMD偏移／RUWE／GaiaNSS）
        │            或後面統計修正（文獻解析修正）
        ▼
用等時線把每顆（剩下的）星的星等換算成質量
        │
        ▼
對這批質量做冪律最大概似估計，得到 α 與誤差棒
        │
        ▼
用「已知答案的假資料」（注入回收）或「對真實資料重抽」（bootstrap）
校準誤差棒，因為 MLE 附帶算出的曲率誤差已知會低估
```

實作在 `traditional_accounting.py`（主控流程）與
`pipeline/step5_imf.py`（質量指派、冪律 MLE 的核心函式）。

## 第三節：資料與等時線（Step 1–2 的推導與程式碼）

# traditional_accounting.py

### 3.2 等時線的單調化處理（為什麼不能直接反查）

等時線給我們「質量 → 星等」，我們要反過來做「星等 → 質量」。這件事
**不是永遠做得到**：如果同一個星等對應到兩個不同的質量，反查就沒有
唯一答案。

問題出在「**主序轉折點**」：恆星在主序階段燃燒氫燃燒到氫用盡時，會
離開主序、往紅巨星方向演化——這個過程中，星會**變亮**但質量並沒有
變大（只是內部結構重新調整）。所以在等時線上，過了轉折點之後，「質量
遞增」不再保證「星等遞減（變亮）」，星等-質量的對應關係不再是一對一。

**解法**：從最低質量開始往高質量掃描，只保留「G 星等持續刷新最小值
（持續變亮）」的那一段，一旦某個質量點的 G 比之前看過的最亮值還暗，
就代表已經開始偏離單調段（很可能靠近或過了轉折點），整段捨棄。

```python
# pipeline/step5_imf.py — main_sequence_mass_luminosity()
m = np.asarray(iso["Mini"], float)                      # 初始質量
g = np.asarray(iso[COL_G], float) + dist_mod + ext.g * av  # 換算成視星等
order = np.argsort(m)
m, g = m[order], g[order]                # 依質量由小到大排序
keep = np.ones(len(m), bool)
gmin = np.inf
for i in range(len(m)):
    if g[i] < gmin:      # 星等比之前看過的都小 = 更亮 = 還在單調段
        gmin = g[i]
    else:
        keep[i] = False  # 沒有刷新最亮紀錄 = 已經偏離單調段，丟掉
m, g = m[keep], g[keep]
idx = np.argsort(g)       # 換成依星等排序，方便下一步查表
return g[idx], m[idx]
```

**這裡的 `dist_mod + ext.g * av` 在做什麼**：等時線給的是恆星「真實」
（如果就放在 10 秒差距外）的絕對星等，但我們觀測到的是「視星等」——
跟距離、還有路徑上的星際塵埃消光都有關。

- `dist_mod`（距離模數）：`5 log₁₀(距離/10 pc)`，距離越遠，視星等
  數字越大（越暗），這是平方反比定律的對數形式。
- `ext.g * av`：消光讓星看起來更暗，`ext.g` 是 G 波段對消光的敏感係數
  （不同波段對塵埃散射的敏感度不同，藍光比紅光更容易被散射掉，所以
  各波段係數不同），`av` 是消光量本身。

把這兩項加上絕對星等，就得到「如果星團在這個距離、有這麼多消光，
這顆特定質量的星『看起來』會是幾等」——這樣才能跟真正觀測到的視星等
直接比較。

### 3.3 質量指派：一行內插

```python
# pipeline/step5_imf.py — assign_masses()
def assign_masses(obs_mag, iso, dist_mod, av, ext):
    g_ms, m_ms = main_sequence_mass_luminosity(iso, dist_mod, av, ext)
    return np.interp(obs_mag, g_ms, m_ms, left=np.nan, right=np.nan)
```

`np.interp` 做的是**線性內插**：我們手上有一串「已知點」`(g_ms[i],
m_ms[i])`（依 g_ms 排序好），給一個新的觀測星等 `obs_mag`，先找到它
落在哪兩個已知點之間，用直線連接這兩點，讀出對應的質量。比喻：像查
一張「身高對照體重」的表，表上只列了某些身高的參考值，你的身高剛好
落在兩筆資料中間，就用直線內插估一個介於兩者之間的體重。超出已知
範圍（`left=np.nan, right=np.nan`）就回傳「不知道」而不是亂外推。

**用哪一條等時線？** 這次擴充後統一用「當下 config C 的最終確認值」
（`logage=8.033、A_V=0.383`，來自前向模型目前最可信的一次擬合
`p2_final2`），而不是舊版用的過時選擇——這樣傳統法跟前向模型才是
在同一個假設下比較（見第九節控制變因討論）。

```python
CURRENT_LOGAGE = 8.033
CURRENT_AV = 0.383
iso = isomod.isochrone_at(grid, CURRENT_LOGAGE, 0.0)   # MH 固定在 0.0
```

## 第四節：五種雙星處理變體，一步步講

### 4.0 為什麼雙星是個問題

太空中的「未解析雙星」是兩顆離得很近、望遠鏡分不開的恆星，我們看到
的是它們**光度相加**後的一個光點。如果直接把這個光點當成一顆單星去
查質量，會得到一個**偏高**的質量——因為它比任一顆成員星本身都亮，
單星等時線會把它對應到一個更重的假想單星。

這件事對整條質量函數的影響方向明確：真正該落在低質量段的兩顆星，被
誤判成一顆偏重的星，等於把統計權重從輕質量端搬到重質量端，**讓 α
（冪律的陡峭程度）看起來變平**——這正是我們要量化、修正的效應。

### 4.1 全當單星（忽略雙星）——基準線

什麼都不做，直接進第三節的質量指派。這是幾乎所有 Gaia 之前的傳統法
論文的隱含預設（沒有特別處理雙星）。

### 4.2 CMD 偏移剔除法

**核心想法**：一顆真正的單星應該落在單星主序上；一顆未解析雙星因為
多了伴星的光，會比同顏色的單星**亮**一些。亮多少可以推算：

**推導「等質量雙星亮 0.753 星等」**：假設兩顆完全相同的星合成一個
光點，總光通量是單星的兩倍，`F_total = 2 F_single`。代入星等公式：

    m_total = −2.5 log₁₀(2F_single) + 常數
            = −2.5 log₁₀(2) − 2.5 log₁₀(F_single) + 常數
            = m_single − 2.5 log₁₀(2)

`2.5 × log₁₀(2) = 2.5 × 0.301 = 0.753`。所以

    m_total = m_single − 0.753

星等變**小**代表變**亮**，所以等質量雙星比單星亮 0.753 星等——這就是
`pipeline/step4_binaries.py` docstring 提到的那個數字的完整來源，不是
憑空給的常數。

質量比不是 1 的雙星（伴星比較輕），加的光比較少，亮度增量介於 0（伴星
完全沒貢獻）到 0.753（等質量）之間。門檻設在**一半**（0.375 星等），
是在「抓到中高質量比的真雙星」跟「不要把單星的正常測光雜訊誤判成雙星」
之間找平衡點。

```python
# pipeline/step4_binaries.py — flag_cmd_offset() 的邏輯
# （traditional_accounting.py 的 ms_colour_to_g + 主流程重新實作了同樣邏輯）
g_expect = np.interp(obs_color, c_iso, g_iso)   # 同顏色下，單星「應該」多亮
excess = g_expect − obs_mag                     # 亮多少
is_bin = excess > threshold_mag                 # 超過門檻 = 判定為雙星
```

**這個方法會犯兩種錯**（見第九節結果）：
- **偽陽性**：測光雜訊或差異消光會讓一些真正的單星「看起來」偏亮，
  被誤判剔除（即使假資料裡完全沒有雙星，f_bin=0 時仍然剔除了約 15 顆）。
- **系統性選擇**：這個方法對「質量比接近 1」的雙星最敏感（它們最亮），
  優先抓到的正是「主星本身就偏重」的那批雙星，整組移除等於系統性
  刪掉重星，讓剩下的質量函數看起來比真實更陡（α 偏高）。

### 4.3 RUWE 剔除法

RUWE（renormalized unit weight error，重整化單位權重誤差）是 Gaia
天測管線的一個品質指標：Gaia 對每顆星在天空中的位置做很多次觀測，
用「一個點沿一條軌跡穩定移動（自行+視差）」這個單星模型去擬合。RUWE
量的是這個擬合殘差有多大，正常值接近 1.0；如果一顆星其實是兩顆星
（未解析雙星），它們共同的「光度重心」會隨著彼此互繞而擺動，單星模型
擬合不好，RUWE 會偏高。

```python
# pipeline/step4_binaries.py
def flag_ruwe(t, threshold):
    return np.asarray(t["ruwe"], float) > threshold   # 門檻 1.4
```

**注意（LIMITATIONS.md 已記錄的教訓）**：RUWE 高不是只有雙星會造成
（也可能是測光/天測品質本身不好），**不能拿 RUWE < 1.4 當一般的資料
品質篩選**——這樣會誤刪 12% 的真成員（M45 年輕、雙星比例高，很多真
成員本來就 RUWE 偏高）。RUWE 只能拿來當「雙星指標」，不能當「品質切」。

文獻依據：Lindegren et al. (2021), *Gaia Early Data Release 3:
Astrometric solutions*, A&A 649, A2。

### 4.4 Gaia NSS 剔除法

Gaia 官方除了發布單星解，也對疑似多重星系統跑更精細的分析（天測軌道
解、光譜雙星解、食雙星解等），把有足夠證據的系統收進
non-single-star（NSS）目錄，`non_single_star` 這個旗標非零就代表官方
判定為多重星。

```python
# pipeline/step4_binaries.py
def flag_nss(t):
    if "non_single_star" not in t.colnames:
        return np.zeros(len(t), bool)
    v = np.asarray(t["non_single_star"], float)
    return np.nan_to_num(v, nan=0.0) > 0
```

我們的樣本裡只有 24 顆（2.2%）被標記——Gaia 的 NSS 判定很保守，只收
證據確鑿的案例，所以完整度低但幾乎不會有偽陽性，是三個「逐星剔除法」
裡最乾淨也最保守的一個。

文獻依據：Gaia Collaboration, Arenou et al. (2023), *Gaia DR3: Stellar
multiplicity, a teaser for the hidden treasure*, A&A 674, A34。

### 4.5 文獻解析統計修正法——不同的哲學

前面三種都是「先猜哪些星是雙星，剔除它們」，但我們已經看到這個做法
本身會犯系統性的錯（CMD 剔除法系統性刪重星）。**另一種哲學**：不去
猜個別哪些星是雙星，而是承認雙星整體上對質量函數斜率有一個已知方向
與量級的偏差，直接用文獻算出的**族群層級**修正量去修正結果。

Rosen (2026, arXiv:2603.15779) 用數值模擬量出：忽略未解析雙星（光度
相加的效應，正是我們的情境）會讓量到的 α 偏低（更平）**0.011 到
0.021**。我們取這個區間的中點 0.016，直接加回「全當單星」量到的 α：

```python
ANALYTIC_CORRECTION = 0.016
if variant == "analytic_correct" and np.isfinite(alpha):
    alpha = alpha + ANALYTIC_CORRECTION
```

**這個做法的優點**：不需要判定任何一顆星是不是雙星，完全不會有前三種
方法的「逐星判準犯錯」問題。**代價**：這個修正量是從別的星團的模擬
量出來的，假設我們的雙星族群跟文獻模擬的族群夠像；而且我們只用了
區間中點，沒有把文獻本身給的不確定範圍（0.01 寬）傳播進誤差棒——這是
已知、記在 LIMITATIONS.md 的簡化，不是隱藏的問題。

**2026-08-11 訂正：這不是獨立驗證，是內部一致性檢查**——原本這裡寫
「這個假設被我們自己的注入回收獨立驗證了」，用詞錯誤。我們的合成雙星
生成邏輯（兩顆星流量相加再換算回星等）跟 Rosen (2026) 修正量鎖定的
「光度加總」偏差機制是同一套物理假設，用同一套假設生成的資料去測試
針對這套假設設計的修正量，測到的是「套用邏輯自洽」，不是「0.016 這個
數字對真實 M45 準不準」。更關鍵的是：**Rosen (2026) 的偏差區間是在
alpha=1.60–2.30 量出來的，M45 現在的 alpha（2.39–2.46）已經超出這個
範圍**，套用區間中點是外推不是內插。注入回收偏差 +0.003 這個數字
仍然值得記錄（代表套用邏輯本身沒有實作錯誤），但不能再拿來宣稱
「0.016 對我們的資料集是準的」。完整討論見 `LIMITATIONS.md`。

## 第五節：冪律的最大概似估計——完整數學推導

這是整支程式最核心的數學，我們從最基本的「什麼是概似」開始推。

### 5.1 用擲硬幣建立直覺

想像你擲一枚不知道是不是公正的硬幣 10 次，得到 7 次正面、3 次反面。
你想估計「擲出正面的機率 p」。對任何一個候選值 p，這組資料出現的
機率是：

    L(p) = C(10,7) · p⁷ · (1−p)³

這個 L(p) 叫做**概似函數**（likelihood）——它不是「p 是多少的機率」
（那是貝氏統計的另一件事），而是「假設 p 是這個值，我實際觀測到的
這組資料有多大機率發生」。**最大概似估計法（MLE）**的精神就是：選一個
p，讓你手上這組**已經發生的**資料出現的機率最大——直覺上，這是「最
能解釋你觀測到的東西」的參數值。

我們對 α 做的事，精神上完全一樣，只是把「離散的正反面」換成「連續
的質量」。

### 5.2 連續量的機率密度

質量是連續的，不能問「質量剛好等於 1.234567... 太陽質量的機率是多少」
（對任何連續分布這個機率都是 0）。改用**機率密度函數** ξ(m)：一顆星
質量落在一個很窄的區間 [m, m+dm] 的機率是 ξ(m) dm。要成為合法的機率
分布，全部積起來要等於 1：

    ∫[m_lo 到 m_hi] ξ(m) dm = 1

### 5.3 正規化係數怎麼推出來

設 ξ(m) = C · m^(−α)，代入上面的條件求 C：

    ∫[m_lo 到 m_hi] C · m^(−α) dm = 1

用冪函數的積分公式 `∫ m^n dm = m^(n+1)/(n+1)`（這裡 n = −α）：

    C · [ m^(1−α) / (1−α) ]（從 m_lo 到 m_hi） = 1

    C · ( m_hi^(1−α) − m_lo^(1−α) ) / (1−α) = 1

    C = (1−α) / ( m_hi^(1−α) − m_lo^(1−α) )

這個式子在 α = 1 時會除以零（需要另外用對數形式處理，但我們關心的
α 落在 2.3–2.5 附近，用不到這個特例）。對照程式碼：

```python
# pipeline/step5_imf.py — mle_powerlaw() 內部
denom = m_hi ** (1 - alpha) - m_lo ** (1 - alpha)
c = (1 - alpha) / denom
```

一模一樣，這不是憑空寫的公式，是從「機率密度積分等於 1」直接推出來的。

### 5.4 n 顆星一起看：概似函數與對數概似

假設我們有 n 顆星的質量 m₁, ..., mₙ，彼此獨立地從同一個分布 ξ(m)
抽出。n 個獨立事件同時發生的機率是各自機率的**乘積**：

    L(α) = ξ(m₁) · ξ(m₂) · ⋯ · ξ(mₙ) = ∏ᵢ C · mᵢ^(−α)

直接乘一大串數字在電腦裡容易數值下溢（很多小於 1 的數連乘會變成
極小的數，電腦浮點數表示不了），而且乘積不好微分。取對數把乘積變
加總（log 的性質：`log(ab) = log a + log b`），而且 log 是嚴格遞增
函數，最大化 L(α) 跟最大化 ln L(α) 是同一件事：

    ln L(α) = Σᵢ ln(C · mᵢ^(−α)) = n·ln C − α·Σᵢ ln(mᵢ)

對照程式碼：

```python
# pipeline/step5_imf.py — mle_powerlaw()
slog = np.sum(np.log(m))
def neg_ll(alpha):
    ...
    c = (1 - alpha) / denom
    return -(n * np.log(c) - alpha * slog)   # 取負號，因為後面要「找最小值」
```

`neg_ll` 就是 `−ln L(α)`；找 `ln L` 的最大值等於找 `neg_ll` 的最小值
——這只是工程上的習慣（大多數最佳化函式庫預設找最小值），數學上是同
一件事。

### 5.5 怎麼找到最大值：解不出公式，只能用電腦搜尋

如果 ξ(m) 是常見的簡單分布（比如常態分布），對 `ln L` 微分、令
導數為零，通常可以解出一個乾淨的公式（例如常態分布的 MLE 剛好就是
樣本平均值）。但這裡的 C 本身是 α 的複雜函數（`m_hi^(1−α)` 這種形式），
對 α 微分後解不出封閉解——沒有一個公式可以直接算出 α_hat 是多少。

**解法：數值搜尋**。程式用 `scipy.optimize.minimize_scalar`，概念上
就是：在合理範圍（0.1 到 5.0，物理上 α 不可能是負的或大到離譜）內，
聰明地嘗試不同的 α 候選值（不是笨笨地每 0.001 試一次，而是用二分搜尋
類的策略快速逼近），每次看 `neg_ll(α)` 的值，往變小的方向調整，直到
收斂在最小值附近。

```python
r = minimize_scalar(neg_ll, bounds=(0.1, 5.0), method="bounded")
alpha = float(r.x)
```

### 5.6 誤差棒從哪裡來：概似曲線的「陡峭程度」

**直覺**：如果把 `ln L(α)` 對不同 α 值畫成一條曲線，曲線在最佳值附近
如果**又尖又窄**，代表只要 α 稍微偏離最佳值，資料出現的機率就掉很多
——我們對這個 α 值很有信心。如果曲線**又寬又平**，代表附近一大段 α
值都差不多能解釋資料——我們對答案沒把握。誤差棒，就是要把這個「有多
確定」量化成一個數字。

**推導**：在最佳值 α_hat 附近，用泰勒展開把 `ln L(α)` 近似成一個
拋物線（因為在最大值處一階導數等於零，展開式的第一項自然消失，只留
下二次項）：

    ln L(α) ≈ ln L(α_hat) + (1/2)·L''(α_hat)·(α − α_hat)²

拿這個形狀去比對**常態分布**的對數：一個平均值 μ、標準差 σ 的常態
分布，取對數是

    ln[常態分布(x)] = 常數 − (x − μ)² / (2σ²)

把兩個二次式對齊：`L''(α_hat) 對應到 −1/σ²`，所以

    σ² = −1 / L''(α_hat)     （因為在最大值處 L'' 是負的，−1/L'' 才是正的）

也就是說：**把 α 附近的概似曲線局部近似成一個常態分布鐘形曲線**，
曲線越尖（|L''| 越大）標準差越小、越確定；曲線越平，標準差越大。這叫
**曲率近似**（curvature approximation），是統計上很常見的做法。

程式不解析微分（因為 C(α) 的形式麻煩），改用**數值二階微分**——三個
相鄰點的高度差近似曲率，這是「加速度」概念的推廣（速度是位置的變化率、
加速度是速度的變化率，這裡是概似曲線斜率的變化率）：

    L''(α_hat) ≈ [neg_ll(α+h) − 2·neg_ll(α) + neg_ll(α−h)] / h²

```python
h = 1e-3
d2 = (neg_ll(alpha + h) - 2 * neg_ll(alpha) + neg_ll(alpha - h)) / h ** 2
err = 1.0 / np.sqrt(d2)     # d2 這裡對應到 neg_ll 的曲率 = -ln L 的曲率 = 1/σ²
```

**這個誤差棒有個已知的弱點**：它假設 `ln L` 在附近真的長得像拋物線
（等價於假設概似大致是常態分布形狀）。樣本數不夠大、或概似曲面本身
有偏斜、平台等不規則形狀時，這個近似會失準——而這正是這份文件下一節
要處理的問題：**我們獨立驗證過，這個曲率誤差比真實誤差小了大約 4 倍**。

## 第六節：注入回收——為什麼曲率誤差不夠準

### 6.1 用已知答案考自己

如果我想知道「我這套質量指派 + 冪律擬合的流程，到底有多準」，最直接
的辦法是：拿一批**我自己造出來、答案我早就知道**的假資料，跑一次
完整流程，看跑出來的答案跟真正答案差多少、跑很多次差多少。

這跟任何測量科學校準儀器的邏輯一樣：要驗證一台體重計準不準，你會拿
一個**已知重量**（比如標準砝碼）反覆秤，看讀數跟真實重量差多少、
每次讀數本身晃動多少——而不是直接相信說明書上寫的「精度 ±0.1 公斤」
（那可能是廠商理論值，實測不一定符合，正如我們的曲率誤差理論值
低估了實際散布）。

### 6.2 假資料怎麼造

本專案自己的前向模型（`JointModel`）可以反過來用：給它一組**已知**
的真實參數（年齡、消光、雙星比例、IMF 斜率、金屬量、質量比冪次），
它會生出一批「假的星團」——每顆假星先按照假設的 IMF 抽一個質量，
按照 f_bin 決定要不要配一個伴星（是的話再抽質量比），用等時線換算出
顏色星等，疊上跟真實資料一樣的測光雜訊模型，再套用跟真實資料完全
一樣的測光品質選擇函數（把 1,297 顆篩到 1,078 顆的那道篩子）。

這樣造出來的假資料，統計性質上跟真實 M45 資料幾乎一模一樣，**唯一的
差別是我們知道真正的答案**。

```python
THETA_TRUE = np.array([8.15, 0.15, 0.45, 2.35, 0.00, -0.50])
# 依序：logage、A_V、f_bin、alpha真值、MH、q_gamma
```

| 量 | 值 | 為什麼這樣設 |
|---|---|---|
| α 真值 | 2.35 | Salpeter 值，方便對照 |
| f_bin | 0.00 / 0.30 / 0.45 / 0.60 | 掃過整個範圍，看雙星比例的影響 |
| 差異消光 dav | 0.30 | 與真實世界一致的已知效應 |
| 測光品質選擇函數 | 開啟 | 同上 |
| 顆數 | 1,078 | 與真實觀測相同，統計雜訊量級才一致 |

兩個**刻意對傳統法有利**的設定，所以量到的偏差是**下界**（不是誇大）：

1. 傳統法直接拿到「真的」等時線（真實年齡、消光、金屬量），實務上它
   還得自己擬合這些量，誤差只會更大。
2. 統計散布用同一批 1,078 顆量，與前向模型完全同基準。

### 6.3 跑很多次、看散布

對每個情境（每個 f_bin、每個變體），用 20 個不同的亂數種子各造一批
假資料，跑一次完整的傳統法流程，記下算出來的 α。20 次結束後：

- **平均值 − 真值 = 偏差（bias）**：這套方法系統性地偏高還是偏低？
- **標準差 = 統計散布（scatter）**：就算方法本身沒有系統誤差，光是
  隨機雜訊本身會讓答案跳動多少？

```python
for t in range(args.trials):
    fc, fm = make_fake(base, th, n_obs, seed=5000 + 31 * t,
                       dav=args.dav_true, selection=sel)
    a, n, n_rm, _ = traditional_alpha(fc, fm, iso_true, dm, av_true, ext,
                                      rlo, rhi, variant=variant)
    outs.append(a)
outs = np.array(outs)
# outs.mean() - a_true = 偏差；outs.std() = 統計散布
```

這個「散布」才是傳統法真正該用的誤差棒——不是第五節那個理論上算出來
的曲率誤差。實測結果：曲率給的 ±0.069，注入回收給的散布落在
0.06–0.12 之間（依變體與情境而定），確認曲率誤差確實低估。

## 第七節：Bootstrap——RUWE/NSS 沒辦法注入回收怎麼辦

RUWE 剔除法跟 GaiaNSS 剔除法有一個結構性的限制：**造假資料的
`make_fake()` 只會產生顏色跟星等**，不會模擬「這顆假星的 RUWE 是多少」
或「Gaia 官方會不會把它收進 NSS 目錄」——這兩個是真實觀測（天測解算、
官方多年分析）的產物，沒有簡單的公式可以正向模擬。

**退而求其次：Bootstrap（拔靴法）**。不造新的假資料，而是對**真實的
1,078 顆星做「取後放回」的重抽樣**：每次隨機抽 1,078 顆（同一顆可能
被抽中好幾次，也可能完全沒被抽到），重新跑一次傳統法流程，重複很多次
（這裡用 1,000 次），看這些結果的散布。

```python
def bootstrap_alpha_err(color, mag, ..., n_boot=1000, seed=7000):
    rng = np.random.default_rng(seed)
    n = len(color)
    outs = []
    for _ in range(n_boot):
        idx = rng.integers(0, n, n)     # 取後放回抽 n 個索引
        a, *_ = traditional_alpha(color[idx], mag[idx], ...)
        if np.isfinite(a):
            outs.append(a)
    return np.mean(outs), np.std(outs)
```

**直覺**：這模擬的是「如果我們當初剛好觀測到（稍微不同組成的）另一批
1,078 顆星，答案會不會差不多」——量的是**對這個特定樣本組成的敏感度**。

**這跟注入回收量的不是同一件事**，要誠實區分：

| | 注入回收 | Bootstrap |
|---|---|---|
| 資料來源 | 造假的合成星團 | 真實觀測，重抽 |
| 量的是 | 對真實但未知的星團真值，方法會偏差、散布多少 | 對這一組特定樣本，答案有多敏感 |
| 能不能量偏差（bias） | 能（有已知真值可以比對） | 不能（真實答案本來就不知道） |
| RUWE/NSS 能不能用 | 不能 | 能 |

論文裡 RUWE、GaiaNSS 兩欄的誤差是 bootstrap，跟其他欄（注入回收或
曲率）不是同一把尺，**只能比中心值，不能直接比誤差棒大小**。我們也
順便對「全當單星」「CMD 剔除」各跑一次 bootstrap 當交叉檢查——量到
0.107、0.108，跟注入回收的 0.118、0.121 量級接近（不要求相等，只要
求同量級），是個放心的訊號。

## 第九節：這些結果告訴我們什麼

**發現一：雙星處理方法的選擇，在對齊質量範圍與正確 isochrone 之後，
對 M45 的 α 幾乎不影響。** 五種傳統變體全部落在 2.37–2.42，彼此差距
（≤0.05）遠小於各自的統計誤差（~0.12）。這是用五種業界常見做法系統性
比較才看得出來的結論——先前只做兩種變體時看不到這麼強的訊號。

**發現二：文獻解析修正法在這批資料上表現最好。** 不逐星剔除、直接套
文獻修正量的做法，在注入回收裡幾乎無偏，優於會系統性過矯正的 CMD
剔除法。這暗示「族群層級統計修正」可能是比「逐星判定剔除」更穩健的
策略——至少對這個資料集是如此。

**發現三：傳統法（2.37–2.42）跟前向模型（2.387）高度吻合。** 這是兩套
**完全獨立的方法論**互相印證，跟「同一個前向模型換一條等時線」那種
同架構換零件的穩健性測試不同類別（後者，即表 4 的 PARSEC vs MIST
比較，已經在另一次檢驗中被發現不夠可靠——鎖住金屬量後兩套等時線給出
的年齡直接矛盾，細節見 `PAPER_OUTLINE.md` 表 4 段落與
`LIMITATIONS.md` 第四節）。傳統法跟前向模型這個交叉驗證沒有受那個
發現影響，因為它測試的是完全不同的兩條分析路徑會不會收斂到同一個
答案，不是同一套模型換零件。

**控制變因對齊表**（跟前向模型比較時，哪些做到了、哪些結構上做不到）：

| 變因 | 對齊狀態 |
|---|---|
| 觀測資料 | 一致，同一批 1,078 顆星 |
| 質量範圍 | 一致，主表只用 0.50–2.50（跟前向模型 alpha 定義域相同） |
| isochrone | 一致，用當下 config C 最終確認值 |
| 統計誤差核算 | 大致一致（全當單星／CMD剔除／文獻解析修正用注入回收），RUWE/NSS 結構上做不到，改用 bootstrap |
| 差異消光 dav | **做不到**，傳統法完全沒有消光自由度，這是兩個方法本質上的差異，不假裝一致 |

## 第十一節：這支程式沒有回答的問題

- 傳統法自己擬合年齡的誤差（我們直接給它 config C 的最佳值，對它有利）
- 質量分層造成的偏差有多大（在有限半徑內量，質量函數必然偏平；第 0 節
  已經提到我們**測到了**分層存在的訊號——α 隨半徑從 1.77 升到 2.29——
  但這只是「範圍內部有結構」，不是「範圍外漏掉多少輕星、漏了會讓
  全樣本 α 偏多少」，這個換算量還沒有人算過，是 PDMF vs IMF 這個
  固有限制目前唯一還沒填的洞）
- 等時線本身的物理錯誤（注入回收看不到，因為假資料本身也是同一套
  等時線生成的——這正是為什麼還要另外做 PARSEC vs MIST 比較，見
  `LIMITATIONS.md` 第四節）
- RUWE／GaiaNSS 兩欄的 bootstrap 誤差，嚴格說跟其他欄不是同一把尺
  （見第七節），只能比中心值
- 文獻解析修正法用的是文獻區間的中點（0.016），沒有把文獻本身的
  不確定範圍（0.011–0.021）傳播進我們的誤差棒

## 第十二節：給教授報告的講稿大綱

**建議流程（約 5–7 分鐘）**：

1. **問題是什麼**（1 分鐘）：M45 的初始質量函數斜率 α，用兩種完全
   獨立的方法測（傳統法：逐星查表指派質量；前向模型：整批統計聯合
   擬合），確保結果不是只靠單一方法的假設撐起來的。

2. **傳統法怎麼驗證自己準不準**（2 分鐘）：教科書給的誤差棒（概似
   曲率）低估了約 4 倍，改用「已知答案的假資料反覆測」（注入回收）
   校準；雙星處理本身有五種業界常見做法，全部做一輪互相印證，而不是
   只信一種。

3. **結果**（2 分鐘）：五種傳統變體全部落在 2.37–2.42，跟前向模型的
   2.387 高度吻合——秀出第八節那張表。強調「雙星處理方法的選擇，對
   這個資料集幾乎不影響答案」這個結論本身是系統性比較才看得出來的。

4. **誠實的保留**（1 分鐘）：前向模型內部另一個測試（鎖住金屬量後
   PARSEC/MIST 是否還一致）發現先前「換等時線穩健」的說法站不住腳，
   MIST 給出不合理的年齡——這威脅的是前向模型內部的一個特定穩健性
   宣稱，不影響傳統法跟前向模型這個跨方法論的交叉驗證。

5. **下一步**（1 分鐘）：等 P10（前向模型的金屬量先驗一致性修正）、
   P6b（低質量段冪次升格為自由參數）定案後，前向模型的最終數字才能
   真正拍板；P8（跟 Li+2020 的方法論核對）已完成，確認我們的傳統法
   定義沒有偏離主流做法。

**教授可能會問的問題與建議答法**：

- 「為什麼要做五種雙星處理法，不是做一種就好？」
  → 因為先前只做兩種時，CMD 剔除法看起來過矯正，不知道是這個方法本身
  有問題還是雙星處理普遍如此；做五種才能區分「這是某個判準的偏差」
  還是「所有方法都收斂到同一個答案，代表雙星處理本身對這批資料影響
  有限」。

- 「文獻解析修正法的 0.016 這個數字，你怎麼知道對 M45 適用？」
  → 這是誠實的假設，目前站不住腳，不是我們驗證過的結論。原本以為
  「注入回收量到幾乎零偏差（+0.003），獨立驗證了這個假設」，但查證後
  發現這不是獨立驗證：合成雙星的生成邏輯跟 Rosen (2026) 修正量用的
  是同一套「光度加總」物理假設，測到的只是套用邏輯自洽，不是數字對
  真實 M45 準不準。而且 Rosen 的偏差區間只驗證到 alpha=2.30，M45 現在
  的 alpha（2.39–2.46）已經超出範圍，套用區間中點是外推。這個變體已
  降級為案例討論，不再拿來跟其他方法比較準確度（見第四節 4.5、第九節）。

- 「RUWE 跟 GaiaNSS 剔除法的誤差棒為什麼比較小/大，能直接比嗎？」
  → 不能直接比，這兩欄用的是 bootstrap（對真實資料重抽樣），跟其他
  欄的注入回收（對已知答案的假資料反覆測）量的是不同的量，只能比
  中心值。

- 「前向模型內部那個穩健性推翻的發現，會不會讓整個前向模型不可信？」
  → 不會，被推翻的只是「換等時線 alpha 不變」這個特定說法，前向模型
  能處理差異消光、測光選擇函數、雙星聯合擬合的結構性優勢都還在，而且
  這次傳統法交叉驗證（跟前向模型獨立吻合）反而是額外一層佐證。

- 「你們全程講 IMF，但這是現在還留在星團裡的星量出來的，這樣量到的
  不是 PDMF 嗎？」
  → 對，嚴格說是 PDMF。IMF 是星團剛形成時的分布，PDMF 是現在的分布，
  兩者要能互換，前提是質量分層／動力學演化沒有把重星跟輕星的空間
  分布拉開太多。**我們量過這個前提，結果是負面的**：把樣本切成四個
  角距離環帶各自擬合，α 從核心的 1.77 單調升到最外環的 2.29，跟質量
  分層的預期方向一致，是全專案最穩固的結果之一——**質量分層確實在
  發生，不是理論上的假設**。但這個測試只告訴我們取樣範圍*內部*的
  相對結構，沒告訴我們 5.1° 的取樣半徑有沒有大到蓋住全部輕星，還是
  有一部分已經被甩到範圍外沒被算進來——那才是換算成 IMF 真正缺的
  一塊，目前沒有量化。論文用詞也還在訂正，正式稿不會再無條件寫「IMF」。
