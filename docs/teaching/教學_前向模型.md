## 第 0 節：三分鐘摘要

**傳統法的根本限制**（見《教學_傳統法誤差核算.md》）：每顆星當單星查
質量、剔除疑似雙星、對剩下的星做冪律擬合——這條路徑上每一步的誤差都
**單向往下傳**，而且完全沒有處理「星團裡有多少比例的雙星、消光星對星
差多少、暗端有多少星因為測光品質不夠被篩掉」這些會**同時**影響最終
答案的效應。

**前向模型的做法完全不同**：不是「觀測資料 → 逐步推回參數」，而是
反過來——**給定一組參數（年齡、消光、雙星比例、IMF 斜率等），電腦生成
一個「假的」合成星團，拿它跟真實觀測比對像不像，調整參數直到最像為止**。
所有效應（雙星、消光、測光雜訊、測光品質篩選）在同一個模型裡**一次**
生成、**一次**比對，不會有傳統法那種「先固定 A 猜 B，再固定 B 猜 A」
的循環論證問題。

**這份文件在做的事**：從「怎麼生一顆假星」的第一行程式碼開始，一路
推導到「怎麼知道生出來的假星團夠不夠像真的」，再到「怎麼有效率地在
六維參數空間裡搜尋最佳解」，最後誠實檢討我們在搜尋演算法裡踩過的一個
嚴重 bug、以及它讓哪些數字現在必須降級成「待重跑確認」。

**目前的核心結果**（含尚待重跑確認的部分，見第九節與第十二節）：

| 設定 | 說明 | α |
|---|---|---|
| A | 舊模型（無選擇函數、無差異消光） | 2.26–2.35 |
| C | 選擇函數 + 差異消光 | **`p2_final2_v3`：2.382 ± 0.068**（2026-08-20 定案，10 次重複，精修 bug 與金屬量先驗兩個修正都已套用；舊的 `p2_final2` 2.387 ± 0.060 已作廢，見第六節） |

**用詞澄清（跟《教學_傳統法誤差核算.md》第 0 節同一件事，這裡重複一次
是因為本文件也全程用「IMF」這個字）**：模型的**生成端**確實是照著假設
的 IMF 函數形式去抽合成星的質量（見第 3.1 節）——這裡「IMF」是精確
用詞，因為那是我們**假設**的生成規則，不是量出來的東西。但把最佳擬合
的 alpha **拿去解讀成「M45 的初始質量函數斜率」時，跟傳統法一樣**，
嚴格說我們量到的是**現時質量函數（PDMF）**，不是星團剛形成時的 IMF。
這不是純理論擔心：按角距離切環帶重新擬合，α 從核心 1.77 單調升到最外
環 2.29（見《教學_傳統法誤差核算.md》第 0 節），跟質量分層的預期方向
一致，證明 M45 裡確實在發生質量分層。前向模型目前**沒有**檢查取樣的
5.1° 半徑夠不夠大、有沒有漏掉被甩到範圍外的輕星，這是把 PDMF 換算成
IMF 真正缺的一塊，也是 `LIMITATIONS.md`／`PAPER_OUTLINE.md` A 類清單
「PDMF ≠ IMF」列為論文用詞必須訂正的原因。下文沿用「IMF」字樣時，
指的是「模型生成端假設的函數形式」，跟「量到的 alpha 是不是真的等於
星團初始的 alpha」是兩個要分開看的問題。

## 第一節：暖身——傳統法不夠在哪裡，前向模型要解決什麼

### 1.1 傳統法的問題本質

傳統法的四步驟（質量指派 → 冪律擬合）有一個共同特徵：**每一步都假設
前面的步驟已經做對了**。要幫一顆星查質量，得先知道星團的年齡、消光、
金屬量——這些通常是**用另一批獨立的觀測（或另一套擬合）先決定好**，
當成已知常數代進來。如果那些「已知」本身有誤差，誤差會單向傳進最後
的 α，而且傳統法的框架裡沒有機制去回頭修正。

更根本的問題是**簡併**（degeneracy）：年齡、消光、雙星比例、IMF 斜率
這幾個量，對觀測到的色光圖都有類似方向的影響（都會讓主序整體變亮或
變暗、變寬或變窄），**單獨**改變其中一個，效果可能跟改變另一個很像。
如果循序處理——先固定 IMF 斜率跟雙星比例去解年齡，再固定年齡去解
雙星比例——等於是「假設 A 是對的去推出 B，再假設 B 是對的去推出 A」，
這樣算出來的誤差棒會**低估**，而且完全看不到「年齡跟消光其實可能同時
錯一點但加起來剛好對上觀測」這種相關性。

### 1.2 前向模型的核心想法：反過來做

與其「從觀測反推參數」，不如「從參數生成觀測，比對像不像」：

```
猜一組參數（年齡、消光、雙星比例、IMF斜率、金屬量、質量比冪次）
        │
        ▼
用這組參數生成一個「假的」合成星團（幾萬顆假星）
        │
        ▼
把假星團跟真實觀測畫在同一張色光圖（CMD）上比對像不像
        │
        ▼
量化「像不像」這件事（機率/概似）
        │
        ▼
調整參數，讓「像的程度」最大化
```

這個做法的好處：六個參數是**同時**決定合成星團長什麼樣子的，最佳化
演算法在調整任何一個參數時，其他五個參數的影響都還在——不會有「先
固定其他五個」這種人為的循序假設。誤差棒也能正確反映參數之間的
相關性（例如年齡跟消光同時往同一個方向偏一點，觀測起來可能一樣像，
這種相關性在傳統法的循序流程裡完全看不到）。

## 第三節：生成一個「假的」星團——`synthesise()` 完整推導

這是整個前向模型的心臟：給六個參數（`logage, A_V, f_bin, alpha, MH,
q_gamma`），生成一批合成星的 (顏色, 星等)。

### 3.1 從 IMF 抽質量：逆變換抽樣法

**問題**：電腦的亂數產生器只會給你 0 到 1 之間**均勻分布**的亂數 `u`。
我們要的是「照著 ξ(m) ∝ m^(−α) 這個分布」抽出來的質量。怎麼把均勻亂數
「整形」成我們要的分布？

**推導（先做最簡單的單一冪律，範圍 m_lo 到 m_hi）**：定義**累積分布
函數**（CDF）`F(m)` = 「質量小於等於 m 的機率」：

    F(m) = ∫[m_lo 到 m] ξ(m') dm' 
         = [ m'^(1−α) / (1−α) ]（從 m_lo 到 m）× 正規化係數 C
         = ( m^(1−α) − m_lo^(1−α) ) / ( m_hi^(1−α) − m_lo^(1−α) )

（這個積分跟《教學_傳統法誤差核算.md》第五節推正規化係數 C 用的是
同一個冪函數積分公式，只是這裡積到變數上限 m 而不是固定上限 m_hi。）

**關鍵性質**：對任何連續分布，`F(m)` 這個「累積機率」本身是一個介於
0 和 1 之間、均勻分布的隨機變數（這是機率論的標準結果，直覺上：CDF
把整個機率「拉直」成 0 到 1 的均勻刻度，因為 CDF 在機率密度高的地方
爬升快、密度低的地方爬升慢，剛好抵消掉密度不均勻的效果）。**所以反過來**：
如果 `u` 是均勻亂數，令 `F(m) = u` 解出 `m`，這個 `m` 就會服從我們要的
分布 ξ(m)。這就是**逆變換抽樣法**（inverse transform sampling）。

解 `F(m) = u`：

    u = ( m^(1−α) − m_lo^(1−α) ) / ( m_hi^(1−α) − m_lo^(1−α) )
    m^(1−α) = m_lo^(1−α) + u · ( m_hi^(1−α) − m_lo^(1−α) )
    m = [ m_lo^(1−α) + u · ( m_hi^(1−α) − m_lo^(1−α) ) ]^( 1/(1−α) )

給一個均勻亂數 `u`，代進這個公式，直接得到一個服從冪律分布的質量，
不需要「試了不合格就重丟」這種效率較差的作法（拒絕抽樣法）。

**實際的 IMF 是三段式的分段冪律**（Kroupa 2001）：

```python
# pipeline/step3_age.py
IMF_BREAKS = {
    "kroupa": ([0.01, 0.08, 0.5, 200.0], [-0.3, -1.3, -2.3]),
}
```

意思是 0.01–0.08 M☉ 冪次 0.3、0.08–0.5 M☉ 冪次 1.3、0.5 M☉ 以上冪次
2.3（這裡的 alpha 是自由參數，取代寫死的 2.3）。做法是上面推導的
單段版本**逐段**做一次（`sample_imf()` 裡的 `seg_integral` 就是在算
每一段的積分權重），先用權重決定「這個亂數落在哪一段」，再用那一段
自己的逆變換公式解出質量。三段之間的係數 `coef` 由「在分界點兩段
必須算出同一個密度值」（連續性）決定，這裡不深入代數細節，只需要知道
精神跟單段版本完全一樣。

```python
# pipeline/joint_fit.py — synthesise() 節錄
IMF_BREAKS["kroupa"] = (orig[0], [orig[1][0], low_mass, -alpha])
m1 = sample_imf(d["u_mass"][:n], "kroupa", mi.min(), mi.max())
```

**共用亂數的重要性**：`d["u_mass"]` 是**預先抽好、固定不變**的一批
均勻亂數，不是每次呼叫都重新抽。這樣不管 alpha 猜多少，同一批 `u_mass`
永遠對應到「用這批亂數在這個 alpha 下會抽到的質量」——改變 alpha 時，
概似的變化只反映 alpha 本身的效果，不會混進「剛好這次亂數比較幸運」
的雜訊。這是整個模型能拿來做精確最佳化搜尋的前提，不然概似曲面會
坑坑疤疤（蒙地卡羅雜訊），最佳化演算法會卡在假的局部最大值。

### 3.2 決定哪些是雙星：白努利試驗

每顆抽出質量的星，要不要配一個伴星（變成雙星），用**白努利試驗**
（Bernoulli trial，成功機率固定的單次二元試驗）：

```python
is_bin = d["u_bin"][:n] < fbin
```

`u_bin` 是另一批預先抽好的均勻亂數；`u_bin < f_bin` 這個判斷式為真的
機率剛好就是 `f_bin`（均勻分布在 `[0,1]` 上，小於某個門檻 `f_bin` 的
機率就是那個門檻值本身）——這是產生「以機率 p 為真」的旗標最直接的
寫法，跟丟一個不公正的銅板（正面機率 p）本質上是同一件事。

### 3.3 伴星質量比：另一次逆變換抽樣

被標記為雙星的星，要決定伴星質量是主星的幾倍（質量比 q = m2/m1）。
質量比也服從一個冪律分布（冪次是 `q_gamma` 這個自由參數），做法跟
3.1 節一模一樣（逆變換抽樣），只是這次抽的是 q 不是 m：

```python
qg, qm = qgamma, self.c3.binary_q_min   # qm 是 q 的下限
if abs(qg + 1) < 1e-9:
    q = qm * (1.0 / qm) ** u             # qgamma = -1 是特例（對數均勻）
else:
    q = (qm ** (qg + 1) + u * (1.0 - qm ** (qg + 1))) ** (1.0 / (qg + 1))
```

跟 3.1 節的公式對照：這就是把 `m_lo, m_hi` 換成 `q_min, 1`（質量比
上限是 1，因為習慣上把比較重的那顆定義為主星）、把 `−α` 換成
`q_gamma` 之後的同一條逆變換公式。`qgamma = −1` 需要另外處理是因為
第五節那個推導在 `α=1` 時會除以零（分母 `1−α` 變成 0），這裡完全
對應同一個數學狀況，換成對數形式的解（`∫dq/q = ln q`，逆變換公式
自然變成指數形式）。

### 3.4 換算成觀測量：光度相加公式

有了主星質量 `m1`（跟可能的伴星質量 `m2 = m1 · q`），查等時線得到
各自的星等，如果是雙星就要把兩顆星的光**加起來**（就像
《教學_傳統法誤差核算.md》第 4.2 節推導 0.753 星等門檻用的同一個
公式，這裡是反過來用它去合成，不是用它去偵測）：

```python
arr[is_bin] = -2.5 * np.log10(10 ** (-0.4 * arr[is_bin])
                              + 10 ** (-0.4 * second))
```

`10 ** (-0.4 * m)` 是把星等換回光通量（星等公式 `m = -2.5 log10(F)`
的反函數：`F = 10^(-0.4m)`），兩顆星的通量相加，再用星等公式換回去。
跟傳統法文件推導的「等質量雙星亮 0.753 星等」是同一條數學關係式的
一般化版本（那裡是 F1=F2 的特例，這裡是任意質量比）。

### 3.5 差異消光：為什麼用對數常態，不能用截斷常態

星團裡每顆星前方的塵埃量不完全一樣（星團有一定的空間延展、塵埃分布
不均勻），所以每顆星實際的消光 `A_V,i` 會圍繞著星團平均值 `A_V` 有
星對星的散布，這個散布量叫 `dav`。

**第一次嘗試失敗的做法**：`A_V,i = max(0, A_V + dav · z)`（z 是標準
常態亂數，`max(0, ...)` 是因為消光physically不能是負的）。**這樣做
被注入回收測試揪出問題**：`max(0, ...)` 這個「截斷」動作，讓實際的
平均消光變成 `A_V` 跟 `dav` 兩者混合出來的一個函數（不再單純等於
`A_V`）——結果是 `A_V=0、dav 夠大` 可以跟 `A_V=0.15、dav 較小` 產生
幾乎一樣的觀測效果，兩者**無法分辨**（簡併）。實測擬合時 A_V 會被
推到 0（貼物理下界），dav 則跑到不合理的偏大值去補償——這正是第六節
`check_walls()` 要抓的「物理邊界」貼牆狀況。

**改用對數常態分布**：`A_V,i = exp( ln(A_V) − s²/2 + s·z )`，其中
`s² = ln(1 + (dav/A_V)²)`：

```python
if dav <= 0 or av < 1e-6:
    av_i = av
else:
    s2 = np.log1p((dav / av) ** 2)
    av_i = np.exp(np.log(av) - 0.5 * s2 + np.sqrt(s2) * d["z_av"][:n])
```

對數常態分布有三個關鍵性質（這裡先接受結論，完整推導需要用到指數
函數的動差生成函數，超出高一範圍，但直覺可以這樣理解）：

1. **恆正**：`exp(...)` 的輸出永遠大於 0，不需要 `max(0, ...)` 這種
   人工截斷，物理上「消光不能為負」這件事被分布形式本身保證，不是
   靠事後修補。
2. **平均值恰好是 A_V**：`s²/2` 那一項的作用正是抵消掉對數常態分布
   本身「平均值會偏移」的效應，讓整批 `A_V,i` 的平均值精確等於我們
   指定的 `A_V`，不會像截斷常態那樣被混合污染。
3. **A_V → 0 時整批 A_V,i 也跟著 → 0**：不管 dav 多大，只要 A_V 趨近
   於零，`ln(A_V)` 趨近負無窮，`exp(...)` 的結果也趨近於零——這在
   結構上直接切斷了「A_V 很小、dav 很大也能模仿出消光」這條簡併路徑，
   跟截斷常態的行為完全不同。

物理上也合理：星際塵埃是沿著視線方向一層層疊加的**乘性**遮光效應
（穿過兩倍厚度的塵埃，透過的光是穿過一倍的平方，不是相減），對數
常態（本質上是「取對數之後變成常態分布」）比一般的常態分布更貼近
這種乘性過程的統計行為。

### 3.6 疊上測光雜訊

```python
g += d["z_g"][:n] * _interp_err(g, self.errmodel, "e_g")
```

每顆合成星的星等加上一個「雜訊項」：標準常態亂數 `z_g` 乘上「這個
星等大概會有多少測光誤差」（從真實資料量出的星等-誤差關係內插而來）。
BP/RP 兩個波段的誤差查表方式，這份專案曾經有個已知現役簡化（用 G
星等去查 BP/RP 的誤差，對紅星會低估），詳細討論見
`LIMITATIONS.md`「已知現役假設」章節，不在此展開。

### 3.7 套用測光品質選擇函數

真實資料從 1,297 顆篩到 1,078 顆，而且**不是隨機篩的**：暗端的紅星
比藍星更容易因為訊噪比不足被砍掉。如果合成星團不套用同一組篩子，
會生出觀測裡已經被砍掉的暗紅星，逼著擬合去用其他參數（通常是 alpha）
硬補這個系統性落差。

```python
if self.selection is not None:
    keep &= self.selection.keep(g, bp, rp, d["z_snr"][:n], d["u_sel"][:n])
```

`SelectionModel.keep()`（`pipeline/selection.py`）把「這個波段的訊噪
比會不會通過門檻」建模成「星等的非參數函數 + 顏色的線性項」（細節見
`pipeline/selection.py` docstring），本質上是同一套「用觀測資料迴歸
出一個經驗關係，套用到合成資料上」的想法，跟前面的測光誤差模型是
同一個哲學：不是憑空假設一條理論曲線，而是直接用資料本身量出關係。

## 第四節：概似函數——Hess 圖與 Poisson 概似的完整推導

生出一批合成星之後，要量「這批假星團，跟真實觀測像不像」，用一個
數字表示。

### 4.1 為什麼要分箱：Hess 圖

把 CMD（顏色-星等平面）切成一個個小格子（例如顏色方向切幾十格、
星等方向也切幾十格），數每個格子裡有幾顆星，這張「每格星數」的表叫
**Hess 圖**。分箱之後，觀測跟合成星團都可以表示成同一種格式（每格的
星數，或正規化後每格的機率），才有辦法用同一套統計工具比較。

```python
# pipeline/step3_age.py — hess()
h, _, _ = np.histogram2d(color, mag, bins=[cbins, mbins],
                         range=[crange, mrange])
s = h.sum()
return h / s if s > 0 else h    # 正規化成機率密度
```

### 4.2 Poisson 分布：從二項式推導

**建立直覺**：想像把 1,078 顆星一顆一顆丟進 Hess 圖的某個特定格子，
每顆星丟進「這一格」的機率是 `p`（一個很小的數，因為總共有幾十x幾十
= 幾千格）。這是標準的**二項式分布**（n 次獨立試驗，每次成功機率 p，
問成功次數的分布）——這正是第五節第一段（見教學_傳統法誤差核算.md
的擲硬幣類比）處理過的同一種分布。

**當 n 很大、p 很小、但 n·p（平均落在這格的星數，記成 λ）維持固定
大小時**，二項式分布會趨近一個更簡單的形式，叫 **Poisson 分布**：

    P(k 顆星落在這格) = λ^k · e^(−λ) / k!

（完整的極限推導涉及階乘的近似，這裡不展開，只需要知道：星數很多、
格子很多、每格期望星數不太大時，Poisson 分布是二項式的一個很好的
簡化近似，而且只需要一個參數 λ 就能完全描述，比二項式方便處理。）

Hess 圖的每一格，觀測到的星數（乘上總星數換算成計數）跟模型預測的
期望星數 λ，都可以用 Poisson 分布去比對「這個觀測結果在這個模型底下
有多可能」——跟第五節傳統法冪律 MLE 的邏輯一模一樣：把每一格的 Poisson
機率**取對數、加總**（獨立格子的聯合機率是各自機率的乘積，取對數變
加總），得到整張 Hess 圖的對數概似。

### 4.3 均勻離群成分：`outlier_frac`

實務上模型不會完美，尤其是模型密度算出來剛好是零、但觀測那一格卻有
星的情況（測光雜訊、殘留場星污染、或單純模型還沒描述到的某個效應）
——如果直接用零去算 Poisson 機率，`log(0)` 是負無窮，一顆意外的星
就會讓整個概似崩潰成負無窮，最佳化演算法完全沒辦法在這種尖刺曲面上
運作。

**解法**：讓模型密度是「合成分布」跟「均勻分布」的混合：

```python
mix = (1.0 - outlier_frac) * mod_h + outlier_frac / n_bins
```

`outlier_frac`（預設 0.01，即 1%）代表「有這個比例的星，可能落在
Hess 圖的任何一格」，物理意義是殘留場星污染、變星、測光異常這些沒有
被模型明確描述的成分。這個常數目前是猜的，2026-08-10 的待辦分類體檢
後被重新標記為「現役假設」（不是無關緊要的旁支待辦），詳見
`LIMITATIONS.md`。

### 4.4 為什麼只平滑模型、不平滑觀測

```python
mod_h = hess(syn[0], syn[1], ..., smooth=self.c3.model_hess_smooth)
```

模型的 Hess 圖是用有限筆（幾萬顆）合成星去估計出來的，格子切得細
時，會有很多「剛好沒抽到星」的空格，即使那個位置理論上密度不是零。
如果不做任何處理，參數稍微一動，這些空格的密度在「零」跟「有一點點」
之間翻轉，會造成概似值劇烈跳動（因為 log 在接近零的地方變化極快），
概似曲面長滿尖刺，最佳化演算法會卡在假的峰值上。**對模型的 Hess 圖
做輕微的高斯平滑，讓密度變成連續變化**，可以避免這個問題——但**不能
對觀測做同樣的平滑**：真實觀測只有 1,078 顆，是我們唯一真正擁有的
資料，平滑會抹掉真正的物理特徵（例如雙星序的偏移，量級跟平滑的尺度
接近，平滑會把它一起模糊掉，直接測試過：平滑觀測後 f_bin 被壓到
0.00，訊號消失）。

## 第五節：六個自由參數與先驗

### 5.1 六個參數是什麼

```python
PARAM_NAMES = ["logage", "A_V", "f_bin", "alpha", "MH", "q_gamma"]
```

| 參數 | 意義 | 為什麼要放進模型 |
|---|---|---|
| logage | 星團年齡（對數） | 決定用哪一條等時線 |
| A_V | 平均消光 | 決定星團整體被塵埃遮暗多少 |
| f_bin | 雙星比例 | 前向模型的核心優勢：不用逐星判定，直接讓資料告訴我們整體比例 |
| alpha | IMF 斜率（m>0.5 M☉ 段） | 我們要測的量 |
| MH | 金屬量 | 影響等時線的形狀 |
| q_gamma | 雙星質量比分布冪次 | 決定雙星的伴星通常偏重還是偏輕 |

其中 MH 跟 q_gamma 原本是**寫死的常數**（假設 M45 金屬量接近太陽、
質量比分布是某個文獻值），後來的輪廓測試（固定它們、逐一改變真值、
看 alpha 偏移多少）發現固定 MH 會讓 alpha 偏 0.40、固定 q_gamma 偏
0.10——分別是統計誤差的 133 倍跟 33 倍，遠遠不能忽略，所以升格為自由
參數，讓資料自己決定。

### 5.2 先驗：均勻 vs 高斯

每個參數搜尋的範圍寫在 `config.toml`：

```toml
logage_min = 7.30
logage_max = 8.30
av_min = 0.0
av_max = 0.6
fbin_min = 0.0
fbin_max = 1.0
alpha_min = 1.5
alpha_max = 3.2
mh_min = -0.6
mh_max = 0.6
```

**均勻先驗**：範圍內每個值「先驗機率」都一樣，範圍外機率是零——這代表
搜尋範圍的**邊界會變成一道硬牆**：如果資料真正偏好的值在邊界外，
擬合會被邊界卡住，報出的答案是被邊界（我們自己設的範圍）決定的，
不是被資料決定的。這正是第六節要處理的「貼牆」問題的根源之一。

**高斯先驗**（金屬量用這個）：先驗機率在某個中心值最高，越偏離越低，
但**沒有絕對禁區**，資料夠強時仍能把答案拉離先驗中心：

```python
if self._mh_sigma > 0:
    lp += -0.5 * ((theta[4] - self._mh_mean) / self._mh_sigma) ** 2
```

這個式子的形狀（跟第五節《教學_傳統法誤差核算.md》推導的常態分布
對數形式一樣）本身就是常態分布取對數。中心與寬度取自 Gaia 光譜的
獨立測量（中心 −0.03、寬度 0.10），是跟我們自己的 CMD 擬合機制完全
獨立的資訊來源。**注意**：`fit_real.py` 等七支「產出數字」的腳本
目前寫死關掉了這個高斯先驗（改用均勻先驗），這是一個尚待處理的
已知問題（P10），詳見第九節與 `LIMITATIONS.md`。

### 5.3 為什麼一次擬合比循序擬合好：一個簡化的例子

想像一個簡化情境：你只有兩個未知數 X、Y，觀測資料只給你一個等式
`X + Y = 10`（無限多組解，X、Y 各自都不確定）。如果**循序**處理：
先「假設」Y=3（某個外部估計），算出 X=7；再回頭「假設」X=7 剛剛
算出來的值是對的，去修正 Y……這樣兜圈子，永遠沒辦法呈現「其實 X 跟
Y 是綁在一起變動的，X 偏大一點 Y 就要偏小一點來補償」這個**相關性**。
唯一正確的作法是**同時**承認 X、Y 都不確定，一起考慮所有滿足
`X+Y=10` 的組合，這樣才能正確描述「不確定性」的形狀（一條線，不是
一個點）。

六參數聯合擬合就是這個道理的推廣：年齡、消光、雙星比例、IMF 斜率
之間有實測的強相關（年齡與消光相關係數達 −0.96、金屬量與消光
−0.95），循序擬合會把這些相關性隱藏起來，讓誤差棒看起來比實際更小
（自信但錯誤），聯合擬合才能誠實反映「這幾個參數其實糾纏在一起，
不確定性有多大」。

## 第六節：怎麼找最佳解——多階段網格搜尋，以及我們犯過的一個嚴重錯誤

### 6.1 為什麼不能一次掃過整個六維空間

如果六個參數各自切 20 個候選值，窮舉所有組合是 `20^6` ≈ 640 億種——
每種組合都要生成一次合成星團（幾萬顆星、疊雜訊、套選擇函數），這樣
的計算量完全不可行。這就是**維度詛咒**：參數越多，需要嘗試的組合數
以指數速度爆炸。

**兩種因應方式**：
- **MCMC**（`run_joint.py` 用的方法）：不窮舉，而是用聰明的隨機漫步
  演算法，只在機率高的區域密集取樣，機率低的區域少花力氣。
- **多階段網格搜尋**（`fit_real.py` 系列用的方法，本節主角）：先用
  很粗的格子掃過**整個**合理範圍（找到大概在哪裡），再對找到的最佳點
  附近，用更細的格子重新搜尋一次（提高精確度），重複幾次，逐步逼近。

### 6.2 多階段精修的想法

用一個生活化比喻：找一個藏在操場上某處的東西，你不會逐公分地毯式
搜索（太慢），而是先粗略地把操場切成 10x10 大塊，每塊看一眼哪裡最
可疑，鎖定最可疑那一塊後，再把那一塊細切成 10x10 小塊繼續找，重複
幾次，很快就能逼近到很小的範圍。

```python
# injection_recovery.py — multi_stage_best()（已修好的版本）
cur = list(axes) + extras
bounds = [(a.min(), a.max()) for a in cur]
best, lp = grid_best_parallel(model, cur, n_proc)   # 第一次：掃過整個粗網格
for r in refines:
    nxt = []
    for i, ax in enumerate(cur):
        if len(ax) < 2:
            nxt.append(ax)
            continue
        step = float(ax[1] - ax[0])
        lo = max(best[i] - step, bounds[i][0])
        hi = min(best[i] + step, bounds[i][1])
        nxt.append(np.arange(lo, hi + 1e-9, step / r))   # 在最佳點附近，格距縮小 r 倍
    cur = nxt
    best, lp = grid_best_parallel(model, cur, n_proc)    # 精修一次
```

每一輪精修，把搜尋範圍收縮到「上一輪最佳點左右各一步」，格距縮小
`r` 倍（`refines` 這個參數，通常設 3）。`grid_best_parallel` 把整個
網格的所有候選組合分配給多個 CPU 核心平行算概似，取最大值的那組
參數。

### 6.3 三種邊界，補救方式完全不同

如果搜尋出來的最佳解剛好卡在搜尋範圍的邊緣，代表「答案可能是被我們
設的範圍決定的，不是被資料決定的」——這件事必須被抓出來，而且不同
種類的邊界代表完全不同的問題：

```python
PHYSICAL_LIMITS = {
    "A_V":   (0.0, None),    # 消光不可能為負
    "f_bin": (0.0, 1.0),     # 比例
    "dav":   (0.0, None),
}
GRID_LIMITED = {"logage", "MH"}   # 受限於已下載的 isochrone 網格
```

| 種類 | 例子 | 意義 | 補救 |
|---|---|---|---|
| **物理邊界** | A_V 貼到 0（3.5 節提到的截斷常態失敗案例） | 角落解，模型描述不了資料 | 放寬不可能，要回頭檢查模型本身（例如換成對數常態） |
| **網格邊界** | logage、MH 貼到已下載 isochrone 網格的邊緣 | 受限於實際下載的資料涵蓋範圍 | 重新下載更寬的網格，不是改個數字就好 |
| **搜尋邊界** | 自己設的 config.toml 範圍太窄 | 答案被我自己決定 | 放寬範圍重跑 |

```python
def check_walls(best, bounds, names, allow=(), tol=0.02):
    ...
    hits.append((kind, f"{nm}={best[i]:.3f} 貼{side}..."))
```

`fit_real.py`（產出論文數字的腳本）遇到未預期的貼牆會直接**中止並
報錯**，不會悄悄把貼牆的結果當成正常答案接受——這個機制在本專案已經
攔下過至少五次不該被忽略的邊界問題（見 `injection_recovery.py`
docstring）。

### 6.4 一個嚴重的搜尋 bug，以及誠實面對它的過程

**這裡示範跟《教學_傳統法誤差核算.md》完全一樣的態度**：發現自己的
程式有問題時，完整記錄下來，不是含糊帶過。

**起因**：某次敏感度測試（`profile_outlierfrac.py`）跑了 12 次，
alpha **全部精確等於同一個數字，散布恰好是 0**。這太乾淨了，不像
真實訊號——如果換了不同的亂數種子、甚至換了正在測試的參數，答案卻
連小數點都完全不動，代表搜尋演算法本身可能沒有真正發揮作用。

**追查發現**：上一段 6.2 節的程式碼，原本寫成：

```python
# 修好前的舊版本，有 bug
best, lp = None, -np.inf
for r in refines:
    best, lp = grid_best_parallel(model, cur, n_proc)   # 這裡的 cur 在第一輪還是原始粗網格！
    nxt = 依 best 算出的精修軸
    cur = nxt   # 精修軸算完只是存起來，迴圈沒有下一輪就沒人用它去搜尋
```

當 `refines` 只傳一個值（例如 `"3"`，這是好幾支腳本的 CLI 預設值，
包括這個發現 bug 的 `profile_outlierfrac.py` 本身），迴圈只跑一輪：
那一輪用的 `cur` 還是最原始的粗網格，算出來的精修軸 `nxt` 存進 `cur`
後迴圈就結束了——**從來沒有人真的去搜尋那個精修軸**。回傳的 `best`
其實是純粗網格的搜尋結果，完全沒有被精修過，所以答案只能落在粗網格
的固定間距上（例如 alpha 的粗網格間距是 0.20，答案就只能是 …2.30、
2.50、2.70…這些固定值），小的效應（像 outlier_frac 這種量級很小的
參數改動）根本不足以讓答案跳到下一個粗格點，看起來就像「完全沒有
影響」——但那是**假象**，不是真的沒有影響，只是搜尋精度不夠細，量
不出這麼小的效應。

**修正**（現在的程式碼，見上方 6.2 節）：把「掃過整個粗網格」搬到
迴圈**外面**，先做一次；迴圈裡的**每一次**才是一輪真正的精修搜尋。
現在 `refines="3"` 代表「粗網格 + 一次精修」，`refines="3,3"` 代表
「粗網格 + 兩次精修」，跟函式說明文件字面上原本就該有的行為一致。

**波及範圍**：這個 bug 影響所有沒有明確傳兩個（或以上）`refines`
值的呼叫——包括本文件第八節要報的一些數字。完整的受影響清單、每項
的嚴重程度分級、以及重跑計畫，記在 `LIMITATIONS.md`
「`multi_stage_best()` 精修 bug」一節，這裡不重複，但第八、九節會
在每個引用到的數字旁邊誠實標注目前的可信度。

## 第七節：四種模型設定 A/B/C/D——逐項加回被忽略的效應

`fit_real.py` 用同一批觀測、同一套搜尋，只換模型設定，逐項把舊模型
漏掉的效應加回去，看 alpha 移動多少：

```python
CONFIGS = {
    "A": ("舊模型：無選擇函數、無差異消光", None, None, (1, 5)),
    "B": ("只加選擇函數", sel, None, (1, 5)),
    "C": ("選擇函數 + 差異消光（上界 0.6）", sel,
          np.arange(0.0, 0.61, 0.15), (5, 6)),
    "D": ("選擇函數 + 差異消光（上界 1.2）", sel,
          np.arange(0.0, 1.21, 0.20), (5, 6)),
}
```

| 設定 | 有選擇函數 | 有差異消光 | 用途 |
|---|---|---|---|
| A（舊模型） | 否 | 否 | 現有文獻常見的簡化版本，α = 2.26–2.35 |
| B | 有 | 否 | 單獨測選擇函數的效應 |
| C | 有 | 有（上界 0.6） | 目前的「修正模型」，論文要報的主要設定 |
| D | 有 | 有（上界 1.2） | 交叉檢查：如果放寬 dav 的搜尋上界，alpha 會不會跟著邊界跑 |

D 設定存在的理由：注入回收顯示 dav（差異消光的星對星散布）本身是
**不可辨識**的（給它多寬的搜尋範圍，它就用掉多寬——上界 0.6 時跑到
0.600，放寬到 1.2 就跑到 1.200），這是允許貼牆的已知 nuisance 參數
（第六節「搜尋邊界」那類，`allow_wall=(5,6)` 白名單裡的索引 6）。
既然 dav 自己會貼牆，就要另外確認 alpha 不會跟著牆的位置一起變——
如果 C 跟 D 給出幾乎一樣的 alpha，代表 alpha 不受 dav 貼牆位置影響，
可以放心；如果 C、D 的 alpha 差很多，代表 alpha 被 dav 的邊界間接
污染了。

## 第八節：完整結果

**誠實聲明（呼應第六節 6.4）**：下表的數字有一部分是在
`multi_stage_best()` 精修 bug 修好**之前**跑出來的，精確值待重跑
確認——完整分級見 `LIMITATIONS.md`，這裡在每個數字旁邊標注目前狀態。

| 設定 | α | 精修狀態 |
|---|---|---|
| A（舊模型） | 2.26–2.35 | 較早期結果，精修狀態未逐一回溯 |
| C（**`p2_final2_v3`，目前 headline**） | **2.382 ± 0.068** | 2026-08-20 定案：10/10 次重複到齊，精修 bug（A1）與金屬量高斯先驗（A2）兩個修正都已套用，A1／A2 對 headline 已解除。舊的 `p2_final2`（2.387 ± 0.060）是精修只做到原意一半＋均勻先驗的版本，已作廢 |

**P9：MH 鎖定檢驗（判別表 4 的穩健性主賣點是不是靠 MH 吸收系統偏差
換來的）**：

| | logage（推算年齡） | alpha |
|---|---|---|
| PARSEC（`P9a-redo`） | 8.0–8.1（100–126 Myr） | 2.440 ± 0.180 |
| MIST（`P9c`） | 7.7–7.8（**50–63 Myr，明顯過輕**） | 2.180 ± 0.098 |

⚠ **這批結果沒帶雙值 `--refines`，等於完全沒精修過，α=2.440/2.180
這兩個精確數字與差距 0.26 待重跑確認**。但質性結論（MIST 鎖住 MH 後
給出的年齡 50–63 Myr 明顯不合理）大機率不受這個 bug 影響——粗網格
的 logage 間距只有 0.10，就算精修後數字會挪動，也不可能從 7.7–7.8
挪回 8.0–8.1（M45 公認年齡對應的區間），落差太大，不是精修解析度
能解釋的量級。

## 第九節：這些結果告訴我們什麼

**發現一：修正模型（C）比舊模型（A）更能吸收消光造成的展寬，選擇
函數與差異消光都是必要的效應，不是可以省略的細節。**

**發現二（P9 判別檢驗）：鎖住 MH 之後，PARSEC 跟 MIST 這兩套獨立的
恆星演化模型給出的 alpha 不再一致，而且 MIST 給出的年齡明顯不合理。**
這證實了先前「修正模型後兩套等時線給出一致 alpha（差 0.000）」這個
說法，其實是 MH 這個自由參數在兩邊各自吸收了不同的系統偏差、湊出
表面一致的答案，不是模型真的一致——表 4 的穩健性主賣點必須改寫（詳見
`PAPER_OUTLINE.md` 表 4 段落）。這個質性結論可信；精確的 alpha 數字
待第六節提到的精修 bug 重跑確認。

**發現三（不受精修 bug 影響）：前向模型的 alpha（2.37–2.41 這個
量級）跟傳統法五種變體的真實資料結果（2.37–2.42）高度吻合**——兩套
**完全獨立的方法論**互相印證，這個穩健性不受 P9 那個「同一個前向模型
換等時線」式的內部檢驗問題影響，因為它測試的是兩條完全不同的分析
路徑會不會收斂到同一個答案。詳見《教學_傳統法誤差核算.md》第九節。

**目前擋在「最終數字」前面的待辦（依優先度）**：
1. 用修好的 `multi_stage_best()` + 雙精修（`--refines 3,3` 或更多）
   重跑 P9a-redo、P9c、`p2_final2`，確認精確數字沒有大幅移動
2. P10：移除 `fit_real.py` 裡寫死的均勻先驗覆寫，改回讀 config 的
   高斯金屬量先驗，重跑 config C 看 alpha 有沒有變
3. P6b：低質量段冪次可辨識性驗證，也在精修 bug 的「完全沒精修」
   等級，待重跑

## 第十一節：這支模型沒有回答的問題

- **isochrone 模型本身的系統誤差**：注入回收永遠測不出這個，因為
  假資料本身就是同一套等時線生成的，模型錯，假資料也跟著錯，兩邊
  一致所以測試會通過。這正是為什麼需要另外做 P9（PARSEC vs MIST
  比較）而不能只靠注入回收——見第九節。BHAC15（另一套專為低質量
  前主序設計的模型）目前仍未測。
- **金屬量異常尚未完全解釋**：真實資料上 MH 跑到 +0.18（自由先驗時
  的舊模型），Gaia 光譜給 −0.02～−0.06，差 0.2 dex，代表模型可能在
  用金屬量補償某個沒建模的效應（見 P9 判別檢驗的動機）。
- **`multi_stage_best()` 精修 bug 修好前跑的數字**：精確值待重跑確認，
  完整清單見 `LIMITATIONS.md`。
- **`outlier_frac`、BP/RP 誤差查表方式**：兩個已知現役假設，從未做過
  完整的敏感度測試，`outlier_frac` 的驗證本身又中了精修 bug，需要
  重跑才能真正回答，詳見 `LIMITATIONS.md`。
- **質量分層／動力學演化多大程度換算成 IMF**：第 0 節已經提到我們
  測到分層存在的訊號（α 隨半徑從 1.77 升到 2.29），這是有限半徑觀測
  的固有限制，跟模型本身無關；但「5.1° 夠不夠大、漏掉多少範圍外的
  輕星」這個換算量還沒有人算過，前向模型量到的 alpha 嚴格說仍是
  PDMF，不是 IMF。

## 第十二節：給教授報告的講稿大綱

**建議流程（約 5–7 分鐘）**：

1. **問題是什麼**（1 分鐘）：傳統法每一步循序假設前面已經對了，
   前向模型反過來——猜參數、生成假星團、比對像不像，六個參數一起
   調整，才能正確呈現參數之間的相關性。

2. **模型怎麼生成一個假星團**（2 分鐘）：從 IMF 抽質量（逆變換抽樣，
   跟傳統法冪律 MLE 用的是同一套積分工具，只是反過來用）、決定雙星、
   疊消光跟雜訊、套測光品質選擇函數——秀出第三節的流程圖。

3. **怎麼知道假星團夠不夠像真的**（1 分鐘）：切成 Hess 圖比對
   Poisson 概似，多階段網格搜尋逐步逼近最佳解——強調這是跟傳統法
   完全不同的「同時考慮所有參數」的做法。

4. **誠實的檢討**（2 分鐘）：發現搜尋演算法本身有個精修 bug，已經
   修好，但修好前跑的一批數字（含 P9 判別檢驗的精確值）需要重跑
   確認——強調這是主動查證、不是被動發現，質性結論（MIST 鎖 MH 後
   年齡不合理）大機率站得住，但精確數字要等重跑。

5. **下一步**（1 分鐘）：用修好的程式碼重跑關鍵結果、移除均勻先驗
   覆寫（P10）、確認低質量段冪次可辨識性（P6b），才能真正定案最終
   數字。

**教授可能會問的問題與建議答法**：

- 「為什麼前向模型比傳統法可信？」
  → 不是「前向模型天生比較準」，是它能同時處理消光、雙星、選擇函數
  這些互相糾纏的效應，避免傳統法循序擬合的循環論證問題；而且兩套
  方法在真實資料上給出高度吻合的答案（2.37–2.42 vs 2.37–2.41），
  這個跨方法論的一致性本身就是有力的交叉驗證。

- 「發現搜尋演算法有 bug，那之前報告的數字還能信嗎？」
  → 質性結論（哪個效應存在、方向是什麼）大部分不受影響，因為粗網格
  的解析度不足以推翻方向性的結論；但涉及小數點後兩三位的精確數字
  （例如 P9 的 α=2.440 vs 2.180 這個具體差距）需要重跑確認，這是
  目前排在最前面的待辦。

- 「金屬量先驗被關掉是什麼意思，會不會讓現有數字整個作廢？」
  → 不會整個作廢，但「p2_final2 是最終數字」這個宣稱要暫緩——目前
  用的是均勻先驗而非文獻記載的高斯先驗，需要重跑確認補上先驗後
  alpha 有沒有系統性移動，這是 P10 待辦。
