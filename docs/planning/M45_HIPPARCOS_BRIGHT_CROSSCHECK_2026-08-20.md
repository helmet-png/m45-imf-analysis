# M45 亮星的外部目錄交叉檢查（最小版）

## 這份資料回答什麼？

我們把 M45 中心 5 度、Hipparcos 的 Hp <= 6 亮星列出，再用 Gaia DR3 的 HIP 編號欄位交叉查詢。這不是新的 IMF 計算，而是一份「亮星是否在哪一關消失」的點名表。

資料表在 `results/m45_hipparcos_gaia_bright_crosscheck_2026-08-20.csv`。Hipparcos 是外部亮星目錄；Gaia 欄位來自 VizieR 的 Gaia DR3 鏡像。**表內的星不是因為視差或自行相近就被宣告為成員。**

## 怎麼查的（可重現）

2026-08-20 對 VizieR TAP 執行兩個小查詢：

```sql
SELECT "HIP","RAICRS","DEICRS","Hpmag","Plx","pmRA","pmDE"
FROM "I/239/hip_main"
WHERE 1=CONTAINS(POINT('ICRS',"RAICRS","DEICRS"),
                 CIRCLE('ICRS',56.60083,24.11389,5.0))
  AND "Hpmag" <= 6.0
```

```sql
SELECT "HIP","Source","RA_ICRS","DE_ICRS","Gmag","Plx","pmRA","pmDE","RUWE","BP-RP"
FROM "I/355/gaiadr3"
WHERE "HIP" IN (16664,17309,17489,17499,17527,17531,17573,17579,
                17608,17702,17776,17847,17851,17954,18471,19009,19038)
```

結果為 17 顆 Hipparcos 亮星，其中 13 顆由 Gaia 的 HIP 欄位交叉到。HIP 17531 與 17608 再以其 Hipparcos 座標做 1.08 角秒 Gaia 小範圍查詢，仍沒有結果；這只表示這次查詢沒有可用 Gaia 來源，不能推論原因。

## 最重要的逐關結果

| Hipparcos 星 | Gaia G | 成員機率 P | 有進 `cmd_members.csv`？ | 目前能確定的事 |
|---:|---:|---:|---|---|
| 17489 | 5.441 | 1.0000 | 是 | 完整保留 |
| 17527 | 5.640 | 0.9999 | 是 | 完整保留 |
| 17579 | 5.752 | 1.0000 | 是 | 完整保留 |
| 17776 | 5.428 | 0.9999 | 是 | 完整保留 |
| 17851 | 5.203 | 0.9999 | 是 | 完整保留 |
| 17499 | 3.698 | 0.6371 | 否 | 在 P >= 0.7 成員門檻前離開 |
| 17573 | 3.863 | 0.9999 | 否 | 已通過成員門檻；G < 4.0 的亮端切割足以解釋它不在 CMD |
| 17847 | 3.616 | 0.8397 | 否 | 已通過成員門檻；G < 4.0 的亮端切割足以解釋它不在 CMD |

這份表把先前的問題分開了：

1. **G < 4.0**：至少 HIP 17573、17847 已經通過成員判定卻沒進 CMD；這和設定中的刻意亮端切割一致。
2. **G = 4.0–5.2**：先前追到的 Gaia `65205373152172032`（G=4.173）在 `baseline.dat` 的 P=0.0017，所以是成員判定先排掉，沒有到測光品質關。
3. **G >= 5.2 的外部亮星**：本小清單中的五顆高 P 星能正常進入 CMD，表示不是所有亮星都被系統性遺漏。

## 還不能說什麼

- 這 17 顆是亮星候選清單，不是完整的、外部確認的 M45 成員表。
- 不能從這份表估計高質量 IMF 斜率會改變多少。
- 原始 Gaia 表 `data/m45_r5_g18_plx4.csv` 仍不存在；因此，對未通過 P 門檻的星，不能反推它假如進到第 2 步會不會通過 BP/RP 或訊噪比切割。

## 現在的結論與下一步

亮端問題已拆成兩個可驗證來源：G < 4 的刻意切割，以及至少一顆 G=4.173 星在成員機率階段被排除。下一步若要評估它對高質量 IMF 的影響，應先選用有明確成員機率的外部星團目錄，定義「外部成員」後再做逐星回收率；不能直接把這張亮星表加回樣本。
