# M45 亮星：外部 HR23 成員機率與本專案是否保留

## 最短結論

有：外部 HR23 快照列為高機率成員、但本專案 CMD 沒有保留的亮星。最清楚的是 HIP 17573：HR23 機率 **0.749**、本專案 pyUPMASK 機率 **0.9999**，但 G=3.863 小於設定的 G=4.0，所以被亮端切割排除。這證實了切割真的會移除至少一顆外部高機率亮成員；但它是設定上的刻意切割，並不代表程式默默漏星。

## 資料怎麼比

- 外部：本機保存的 Hunt & Reffert 2023（HR23）M45 快照 `data/hr23_Melotte_22.csv`，共 1,721 筆。
- 本專案：已保存的 Hipparcos–Gaia 亮星表、`results/baseline.dat` 的 pyUPMASK 機率、與 `data/cmd_members.csv`。
- 腳本：`scripts/diagnostics/crosscheck_hr23_bright_stars.py`。

「不在 HR23 快照」只能表示本地快照沒有那筆資料，**不能**當成外部目錄判定非成員。

## 對原本 G=4.0–5.2 疑問的幫助

先前的 Gaia `65205373152172032`（G=4.173）不在此 HR23 快照，且本專案 P=0.0017。因此，這一輪仍不能把它叫做「外部確認成員被錯殺」；只能確認它在本專案的成員門檻就離開。這正是為什麼不能只用相近視差下結論。

目前可以清楚分成兩類：

1. G<4 的亮星：外部高機率案例存在，而且本專案確實因明文設定切掉。
2. G=4.0–5.2：尚沒有同一顆、同時具備外部高機率與本專案低機率的可確認案例；需要一份更完整、版本已核對的外部成員目錄才能量化回收率。

所以 D12 的下一步應是找可版本化的完整 M45 外部成員清單，再預先定義門檻與回收率。現在不應把這些亮星直接加回 IMF 樣本。
