# 從 PDMF 走到 IMF：方法調查、實驗與執行順序

**狀態**：規劃 + 第一個實驗已排程（2026-08-12 起）
**為什麼要做**：這個專案的目標本來就是量 IMF，但目前所有結果嚴格說都只是
PDMF（現時質量函數）。`LIMITATIONS.md` 的 A 類清單裡「PDMF ≠ IMF → 論文
用詞必須正名」是三個威脅現有主張的項目之一，而且是唯一還沒動過的。

---

## 一、先把問題重新框定：質量分層 ≠ 質量流失

這兩件事常被混為一談，但對「PDMF 能不能當 IMF」的影響完全不同：

- **質量分層**是星團**內部重分配**——重星沉向核心、輕星飄到外圍。
  **全域**質量函數完全沒變。只有「只量核心」時才會看到偏平的 α。
- **蒸發／潮汐剝離**才是真的**把星丟掉**，這才會改變全域質量函數。

**結論：PDMF→IMF 的修正量，主要取決於量到多大半徑，其次才是星團演化了多久。**
這也是底下四條路線的分水嶺——路線 A 攻的是前者，路線 B/C 攻的是後者。

## 三、實驗一（已完成，用專案現成資料）：α(r) 梯度有多大

拿 `results/step5_mf_radial.csv` 四個環帶做加權線性擬合：

```
alpha(r) = 1.732 + 0.155·r      斜率 5.5 sigma，chi2/dof = 0.21
0-1°  1.77±0.11    1-2°  2.01±0.12    2-3°  2.15±0.17    3-5.1°  2.29±0.21
```

**核心到外圍 α 差 = 0.515**：

| 對照 | 值 | 倍數 |
|---|---|---|
| 統計誤差 σ_α（注入回收） | 0.144 | **3.6×** |
| 目前最大單一系統誤差（低質量段冪次） | 0.248 | **2.1×** |

**「樣本半徑取多大」是全專案對 α 影響最大的單一選擇，比所有已知系統誤差
都大，而它從來沒被當成誤差項處理過。**

**外推是不可用的**：線性外推到潮汐尾（16.9°）給出 α = 4.35，比任何觀測過
的 IMF 都陡，物理上荒謬。外推法自己破功——這正是「要真的去量、不要外推」
的論據，不是可以拿來用的數字。

### 這個梯度有一個必須先排除的陷阱

上面四個 α 是**傳統法**（`pipeline/step5_imf.py` 的 `mle_powerlaw`）算的，
帶著未解析雙星造成的偏平偏差。而
[Liu, Shao & Li (2025), ApJL](https://iopscience.iop.org/article/10.3847/2041-8213/adbe60)
發現 **Pleiades 的雙星比例隨半徑是雙峰的**（核心與最外圍高、半質量半徑
附近低），低質量端隨半徑單調上升、高質量端隨半徑下降。我們的前向模型
假設**全域單一 f_bin**。

**所以那 0.515 裡有多少是真的質量分層、多少是雙星比例隨半徑變化造成的
假象，目前分不出來。這是實驗二要回答的第一個問題。**

### Converse & Stahler (2010) 實際初始條件（2026-08-12 訂正，準備正式模擬前查證）

之前這份文件與 `WORK_BOARD.md` 都寫「N≈1200–1500 systems、初始雙星比例
~95%、embedded cluster + 氣體驅離」，**這句話不準確，是沒有查證原文就
寫下的**。透過 WebFetch 讀取 MNRAS 論文頁面的 methods 摘要後，實際設定是：

- **起始狀態是氣體驅離後、已達 virial 平衡**（n=3 多方球，virial 半徑
  ~4 pc），**不含胚胎星團／氣體動力學階段本身**——論文原文說這段留給
  未來工作，之前的「embedded cluster + 氣體驅離」寫法把兩件事混為一談。
- **恆星系統數（星＋聯星當一個系統算）最佳擬合值約 400**，不是
  1200–1500。
- **原初聯星比例的先驗範圍是「接近 1」，但最佳擬合值約 0.65–0.68**，
  不是 95%（95% 可能是先驗範圍的上限或另一篇文獻的數字被誤植過來）。
- **IMF 用 lognormal-Salpeter 混合分布**（質量範圍 0.08–10 M☉），不是
  這份文件其他地方常提到的 Kroupa (2001)。
- **初始就帶有顯著的質量分層**（分層程度參數 ~0.5），不是白手起家、
  純靠 125 Myr 動力學演化產生分層——這點對本專案的路線 C 特別重要：
  若要重現該文獻的結果，初始條件本身就要塞入質量分層，不能只等它
  自然發生。
- 積分到 125 Myr，用 starlab 這套 N-body code（不是這裡準備用的
  PeTar），25 次模擬取平均。

**這份訂正的可信度聲明**：以上數字來自 WebFetch 讀取論文頁面 methods
段落的摘要，**沒有比對過論文正式的 Table 1**，N≈400、雙星比例
0.65–0.68 這些是「摘要讀到的最佳擬合值」，精確到小數點的版本要另外
查證。用 PeTar 重跑這個路線時，**不是照抄 400/0.65 這兩個數字去配
starlab 的結果，是拿它們當起點，讓資料（本專案第 2 步的 α(<r) 觀測
基準線）自己決定要不要調整**——跟本專案「分支規則是資料的函數，不是
對特定天體既有認知的函數」的原則一致（見 `CLAUDE.md`）。

### 文獻對 M45 意外地有利

兩篇獨立研究（[Li+2026](https://arxiv.org/html/2606.05762) 163 星團、
[arXiv:2403.08850](https://arxiv.org/abs/2403.08850) 93 星團）都得到：
**α 在 200 Myr 以內基本不變**，明顯偏平要到 ~600–800 Myr 潮汐剝離開始
效率化才發生。把 Li+2026 的分段線性公式
（a₁=−0.083, a₂=3.7, x₀=8.9, y₀=−2.4, s=4.9）代入 M45：

```
logAge 7.0 (10 Myr)  -> alpha = 2.242
logAge 8.097 (125 Myr) -> alpha = 2.318
delta alpha = 0.076   （統計誤差 0.144 的 0.53 倍）
```

**只要量的是全域質量函數，M45 的 PDMF ≈ IMF 這個宣稱站得住，修正量小於
統計誤差。問題不在「星團演化了多久」，而在「我們只量了核心」。**
這反過來讓路線 A 變得特別划算。

⚠ 這個 0.076 目前是**文獻公式代入值，不是我們自己量的**，引用時要標明。

## 五、執行順序與理由

不是 A→B→C→D，而是**先便宜的診斷、後昂貴的承諾**，每一步的結果決定下一步
值不值得做：

### 第 1 步（B，已完成）：文獻基準線
代入 Li+2026 公式得 Δα = 0.076。不是最終答案，是給後面每一步一個**對照
基準**——我們自己量出來的修正量如果跟這個差很多，就要解釋為什麼。

### 第 2 步（A 診斷版，已排程）：前向模型逐半徑重跑 α(<r) ⬅ **關鍵分歧點**
用**前向模型**（會把雙星建模掉）在累積半徑切片上重跑，看兩件事：
1. 扣掉雙星效應後，0.515 的梯度還剩多少？（真分層 vs 雙星假象）
2. α(<r) 到潮汐半徑有沒有收斂？（我們的 r=5° 夠不夠）

**這一步的結果決定路線 A 完整版跟路線 C 值不值得投資**，所以必須排在
它們前面。已加 `fit_real.py --radius-range LO,HI` 旗標（最小改動，重用
既有全部機制；`dm` 刻意仍用全樣本算，只讓徑向選樣一個變因動）。

已排入 `queue.txt`（全部同設定，只有半徑範圍不同，一次只動一個變因）：
`radial_r1`（r<1°, n=355）、`radial_r2`（r<2°, n=735）、
`radial_r3`（r<3°, n=937）、`radial_rall`（全樣本, n=1078）。

### 第 3 步（D）：LIMEPY 多質量平衡模型
用逐質量段的徑向密度剖面擬合多質量平衡模型，反推全域 MF。這是**用物理
取代第三節那個破功的線性外推**——在不重抓資料的前提下估計「潮汐半徑外
還有多少低質量星」。用第 2 步的 α(<r) 當驗證標的。**環境問題已解決、
第一次擬合已跑完，完整記錄見第七節**：正確套件名是 `astro-limepy`
（不是 PyPI 上另一個同名的問卷調查工具 `limepy`），scipy 舊版
`scipy.integrate.ode` API 相容性問題用獨立 venv 釘 `scipy==1.16.3`
解決，修正單位 bug 後 reduced chi^2=0.75（擬合品質好），但質量區間
比例沿用觀測 PDMF 是已知簡化。**2026-08-19 更新**：第 2 步的 `_prelim`
四個值已到齊，可以做探索性的交叉比對（見 `WORK_BOARD.md` 的
`limepy_radial_crosscheck`），但這只是方向性檢查——正式的驗收比對
要等 `radial_final_reruns` 的有誤差棒版本才算數。

### 第 4 步（A 完整版）：放大搜尋半徑，量真正的全域質量函數
r=5° 擴到 8–17°，重抓 Gaia、重跑成員判定、重建選擇函數。**觀測上的決定性
答案**，但工作量最大，所以要等第 2 步證實梯度是真的才投入。**2026-08-19
更新**：第 2 步的 `_prelim` 四個值已到齊（有資料可看），但「證實梯度是
真的」這個條件本身還沒滿足（單次無誤差棒，非單調現象還不能判斷是不是
雜訊）——現況與後續待辦見 `WORK_BOARD.md` 第 4 步條目，兩份文件此處
判斷一致，都要求先有誤差棒版本才投入。

### 第 5 步（C）：N-body
排最後的四個理由：(a) 需要 x64 機器或 WSL 編譯；(b) 初始條件應該由前面
每一步的結果決定；(c) 它是「確認並延伸」而不是「發現」；(d) 這是論文
原創性的賣點，但需要先有觀測基準線才有東西可以比。**2026-08-19 更新**：
`_prelim` 基準線已到齊，可以拿來做初步、探索性的校準方向（見
`WORK_BOARD.md` 的 `nbody_prior_from_radial`），但正式投入完整算力的
校準版本仍要等有誤差棒的最終版本。

## 六、對論文的影響

使用者已確認 **IMF 本來就是這個專案的目標**，不是可選的附加章節。所以這條
線的產出不會只是誤差預算裡多一列，而是：

- 「徑向覆蓋如何主導 α」要成為獨立章節（目前 0.515 的核心-外圍差比所有
  已知系統誤差都大，卻沒被當誤差處理過——這件事本身值得寫）
- 論文用詞正名：現有結果講 PDMF，補上修正後才能講 IMF，且要標明修正是
  怎麼來的（文獻公式 vs 我們自己量）
- `PAPER_OUTLINE.md` 的表 5 誤差預算要新增「徑向覆蓋」一列

**路線 C（N-body）的用詞規範（H15，2026-09-05 使用者要求先定案，之後
所有 N-body 產出的文字比照辦理）**：

1. **`nbody_pdmf_smoke.py` 只是核心演算法的理解佐證，不是科學結果**——
   它自己的 docstring 已經寫得很清楚（"This is a PeTar/AMUSE *pre-flight
   test*, not a production cluster model"），沒有恆星演化、銀河潮汐、
   原初雙星族群、或觀測選擇函數。引用它的輸出時只能說「驗證了分析鏈的
   演算法邏輯」，不能拿來支持任何跟 M45 本身有關的科學主張——這條界線
   要延續到所有未來的 N-body smoke test，不是這一支腳本專屬。
2. **在套用 Δα 修正之前，路線 C 產出的任何質量函數只能稱為「system
   PDMF」，不能稱為 IMF**——這是 A5 的直接延伸：即使 N-body 模擬了完整
   的動力學演化，`petar_pdmf_analysis.py` 輸出的仍是模擬終止時刻（見
   H11）的現時質量函數，要先完成 Δα（現時 vs 初始）的修正、且修正本身
   通過驗證，才能改口叫 IMF。
3. **初始條件本身要標明是「氣體驅散後（post-gas expulsion）」的狀態**——
   直接查證 arXiv:1002.2229 原文確認：Converse & Stahler (2010) 的
   Table 1 初始條件是「起始狀態是氣體驅離後、已達 virial 平衡」（論文
   原文："already had a virial radius... after the cloud gas has been
   expelled"），不含胚胎星團／氣體動力學階段本身。任何沿用這組初始條件
   的 N-body 結果，論文行文都要明確標注「post-gas-expulsion」這個限定，
   不能省略成單純的「初始質量函數」，讀者才知道這不涵蓋更早期、還在
   胚胎階段的物理過程。

踩到兩個真的 Windows 可攜性問題，都已解決：

1. **PeTar 的 `configure` 其實本來就有 Windows 支援**（`case` 分支
   `Cygwin*|Mingw*) build_windows=yes`），但 MSYS2 的 `uname` 回傳
   `MINGW64_NT-...`（全大寫），只匹配到大小寫混合的 `Mingw*`，直接被
   `configure` 判定成不支援的作業系統而中止。修法是把 `configure`
   （已由 autoconf 產生的那份，不是 `configure.ac`）第 3025 行的
   case pattern 從 `Cygwin*|Mingw*` 改成
   `Cygwin*|Mingw*|MINGW*|MSYS*`。改完 `./configure --with-mpi=no`
   （之後要加恆星演化再補 `--with-interrupt=bse`）跟 `make` 都一次過，
   只有一堆無害的 warning。
2. **mcluster（`github.com/lwang-astro/mcluster`）用了三個 MinGW-w64
   runtime 沒有的 glibc/POSIX 擴充函式**：`srand48`／`drand48`
   （48-bit rand48 亂數產生器）跟 `feenableexcept`（浮點例外
   trap，僅除錯用，跳過不影響結果正確性）。寫了一個
   `mingw_compat.c`／`.h`（標準 rand48 LCG 演算法：
   `X_{n+1}=(0x5DEECE66D*X_n+0xB) mod 2^48`，`drand48()=X/2^48`；
   `feenableexcept` 給空實作），在 `main.c` 加一行
   `#include "mingw_compat.h"`，編譯時把 `mingw_compat.o` 一起連結
   進去（`make mcluster_sse CFLAGS='mingw_compat.o -lgfortran'`）。

這兩個修正都是本機（`nbody/` 工作目錄，跟這個 repo 平行、不進版控）
裡對外部工具原始碼的修改，不是這個 repo 的程式碼，所以沒有對應的 PR，
記在這裡讓下一個要在 Windows 機器上重做這件事的人不用重踩一次。

## 八、多星團普適性研究的分層協定（2026-08-15，使用者要求先定案）

**這節管的是「以後每加一個新星團，流程怎麼跑」，不是 M45 這篇的範圍**——
M45 論文本身不受這節影響，這裡先把架構定下來是為了避免以後每加一個新
星團就重新吵一次「這個要不要做動力學校正」，跟 `CLAUDE.md`「架構決策
必須考慮長期」的原則一致：這是要用很多年的協定，不接受先湊合、以後
再改的版本。

### 問題：不同星團若用不同深度的處理，還能比較嗎？

跨星團比較 IMF 普適性，前提是每個星團交出來的數字是**同一個量**。若
甲星團做了完整 N-body 動力學校正、乙星團沒有（因為它明顯不需要），
兩者的「最終 IMF」表面上是同一欄，實際上經過完全不同的方法論加工——
任何觀察到的差異都可能是方法差異而不是真實的物理差異，**這會讓整個
普適性宣稱站不住腳**。但反過來，強迫每個星團不分青紅皂白都跑到最滿
（不管需不需要都做 N-body）也不是答案：N-body 需要餵入質量分層度、
聯星比例、初始密度剖面這些對每個星團都不同、往往缺乏獨立觀測約束的
初始條件，**硬套在不需要校正的星團上，校正本身的不確定性可能比它想
修正的效應還大**，反而引入一個星團間不一致的新誤差來源，比不校正
更傷比較性。

### 解法：把「比較的對象」跟「處理的深度」分開——分兩層，深度可以不同，結構不能不同

**第一層（Tier 1，每個星團無條件都跑，不分情況）**：

1. 本論文建立的整套誤差核算框架（選擇函數、雙星處理、等時線敏感度、
   注入回收統計誤差）——這是「分析選擇誤差預算」本身，不管星團動力學
   狀態如何都要做，這正是本篇論文的核心方法學貢獻可以直接複用的部分。
2. 動力學年齡 τ = age / t_rh（半質量鬆弛時間），公式與算法見本文件
   第二節，任何星團只要有質量、半徑、年齡的估計就能算，成本極低。
3. 路線 A 診斷版：徑向 α(r) 剖面（累積半徑切片重跑前向模型），
   量出核心-外圍差異的顯著度（幾倍統計誤差）。

這一層的輸出（原始 PDMF、τ、徑向梯度顯著度）**本身就是第一個可以
跨星團比較的標準化量**，即使後面完全不觸發任何校正，這一層也已經
產出可比較的結果，不是「還沒開始」。

**第二層（Tier 2，觸發式，門檻要事先訂好、對所有星團套用同一條規則，
不是逐星團主觀判斷）**：

觸發條件（草案，實際數字要在有第二個標竿星團的實測數據後校準，
不要現在憑空定精確門檻）：τ 超過某個值，或 Tier 1 徑向梯度顯著度
超過某個 σ 門檻，就升級跑路線 C（N-body）或 D（LIMEPY）；沒觸發的
星團**不是跳過不管，是明確記錄「未觸發，PDMF≈IMF，校正量上限見下」**。

**未觸發星團的校正量上限**：用同一套推算方法（比照本文件第五節
「文獻對 M45 意外地有利」那段的做法：代入 Li+2026 或類似的 α(age)
經驗公式）算出「如果真的做了校正，量級大概是多少」，當成這個星團
校正項的上限估計，**不是留空**。

### 為什麼這樣能保住比較性

每個星團最後交出來的不是一個裸數字，是一張**結構相同**的誤差預算表：

| 項目 | 有觸發 Tier 2 的星團 | 沒觸發的星團 |
|---|---|---|
| 原始 PDMF ± 統計誤差 | 有（Tier 1） | 有（Tier 1，同一套流程） |
| 動力學校正項 | 實際校正量（Tier 2 算出） | 文獻公式推算的上限估計（不是空白） |
| 其餘系統誤差（等時線／選擇函數／雙星） | 有，跟動力學狀態無關 | 有，同一套流程 |

**表格欄位永遠一致，差別只在「動力學校正」那一列填的是實測值還是
上限估計**——讀者比較時看得出星團間的差異是真實物理還是方法差異
造成的，這是能撐住跨星團普適性宣稱的必要條件，也是這節存在的
唯一目的。
