# M45 的 CMD 樣本有沒有漏掉外部高機率成員？

## 這是在比什麼

我們把兩份已經存下來的名單逐一比對：

- 外部參考：Hunt & Reffert 2023（HR23）M45 快照，1,721 筆；
- 本專案：進入 CMD／IMF 前處理的 `cmd_members.csv`，1,078 筆。

這不是「誰才是真正成員」的裁判。兩個目錄的成員機率算法、天空範圍和品質門檻不同。它只回答一個比較實際的問題：外部目錄中高機率的星，在不同亮度下有多少也走進我們的 CMD 樣本？

## 已驗證結果

以 HR23 機率至少 0.7 的 529 顆外部高機率成員為例，433 顆也在本專案 CMD 中，總重疊率為 **81.9%**。

| Gaia G 星等 | HR23 高機率成員數 | 在本專案 CMD 中 | 重疊率 | 能安全說的事 |
|---|---:|---:|---:|---|
| G < 4 | 1 | 0 | 0% | 符合已知的亮端切割；樣本只有一顆。 |
| 4 ≤ G < 5.2 | 0 | 0 | — | 這份 HR23 高機率快照沒有可檢查的星，不能下結論。 |
| 5.2 ≤ G < 8 | 15 | 15 | 100% | 這個亮度段沒有顯著流失跡象。 |
| 8 ≤ G < 12 | 88 | 86 | 97.7% | 重疊很高。 |
| 12 ≤ G < 16 | 172 | 158 | 91.9% | 重疊仍高，但不是完全一致。 |
| 16 ≤ G < 18 | 219 | 174 | 79.5% | 外部與本專案名單的差距明顯變大。 |
| G ≥ 18 | 34 | 0 | 0% | 本專案 CMD 最暗只有 G=17.925；這段不在目前樣本。 |

把 HR23 門檻放寬到機率至少 0.5，趨勢相同：G=5.2–16 的重疊率約 92–100%，G=16–18 是 79.6%，G≥18 為 0%。完整數字在 `results/hr23_cmd_recall_by_magnitude.json`。

## 這對 IMF 代表什麼

亮端的直接檢查沒有發現 G=5.2–8 的外部高機率成員被系統性漏掉；已知的 G<4 切割則確實移除了至少一顆。另一方面，暗端 G=16–18 的目錄差距比較大，而且 G≥18 完全不在目前 CMD 樣本，因此低質量端的完整性與成員選擇仍然是要清楚寫出的限制。

這些重疊率**不能直接當作 IMF 完整度修正**，因為 HR23 也不是完美真值，且兩份名單的選擇規則不一樣。更不能因為外部有但本專案沒有，就直接把那些星加回 IMF。

## 下一步

若要把這項檢查升級成完整性量化，需要先固定「外部參考成員」的版本、機率門檻、天空範圍與 Gaia 品質規則，再針對同一個輸入星表量化每一步的回收率。目前最安全的用途，是把它當成亮度依賴的外部一致性警示。

## 可重現方式

```powershell
.venv_forward\Scripts\python.exe scripts\diagnostics\check_hr23_cmd_recall.py
```
