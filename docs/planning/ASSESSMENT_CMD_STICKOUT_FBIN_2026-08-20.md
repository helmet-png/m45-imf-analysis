# D13：CMD「凸出星」比例能否幫忙限制聯星比例？

## 一句話結論

**目前不應直接把凸出星比例加進前向模型的似然函數。**

它是有價值的模型檢查：M45 真實 CMD 的凸出星比例，和已完成模型的預測相容。但它由同一張 CMD 算出，而現有 Hess 似然也在用同一批 CMD 點；把兩者當兩份獨立證據相乘，會把同一個訊息算兩次，讓 `f_bin` 的誤差棒假裝變得太小。

## 什麼是「凸出星」？

想像單星主序是一條跑道。兩顆亮度接近的星若在望遠鏡裡黏成一點，會比跑道上同色的單星更亮，位置會落在跑道上方。這裡把「比同顏色單星亮超過 0.3765 等」的星叫做凸出星（stick-out stars）。

這個數量不是聯星比例本身：

- 有低質量伴星的雙星幾乎不會凸出；
- `q_gamma`（伴星質量比的分布）會改變有多少雙星夠亮；
- 測光誤差、差異消光、等時線和品質篩選也都會改變它。

所以它只能是「透過完整模型校正後的代理量」，不能把凸出比例直接翻譯成 `f_bin`。

## 本次不重跑 IMF 的診斷

資料與程式：

- 讀取已完成的正式 M45 `p2final_v3` 十次重複；沒有重新最佳化或抽樣。
- 每次只生成 40,000 顆合成系統，套用同一個選擇函數後量凸出比例。
- 使用原正式跑所記錄的 PARSEC 網格；這份公開快取原本不在專案內，已重新取得，避免拿錯年齡範圍的網格。
- 可重現輸出：`results/stickout_fraction_assessment_p2final_v3.json`；程式：`scripts/diagnostics/assess_stickout_fraction.py`。

| 指標 | 結果 | 怎麼理解 |
|---|---:|---|
| 真實 M45 凸出星 | 62 / 1072 = **5.78% ± 0.71%** | 真實資料的檢查基準 |
| 正式十次模型預測 | **5.80%–7.04%**（平均 6.43%） | 真實值落在模型重複的範圍內 |
| 固定其他參數，`f_bin=0.2 → 1.0` | 凸出比例 **3.25% → 10.10%** | 此量確實對聯星比例有反應 |
| 被凸出門檻抓到的真雙星比例 | 約 **9%–12%** | 多數真雙星不會凸出；它不是完整的聯星普查 |

這支持的只有一件事：**現有 M45 模型沒有在這個獨立的「摘要檢查」上明顯失敗。**它不會產生新的 IMF 結論，也不能說已經獨立測出 `f_bin`。

## 為什麼不能直接加一個 binomial likelihood？

目前似然函數把整張 CMD 切成 Hess 圖的格子，逐格比較模型與資料。凸出星的數量也是從相同的 CMD 格子加總得來。若寫成：

`總機率 = Hess 機率 × 凸出星比例機率`

等同於同一批星在上方區域被計兩次。結果看似更精確，實際上只是過度自信。

## 若未來真的要升格為制約，最低安全做法

1. **先做注入回收。** 用已知的 `f_bin`、`q_gamma`、消光與選擇函數生成假星團，確認方法能回收 `f_bin`，且不會把 `q_gamma` 或 `dav` 的變化誤認為聯星比例。
2. **避免重複計數。** 二選一：
   - 把凸出區域的 Hess 格從原 Hess 似然移除，再用凸出/非凸出計數取代；或
   - 從大量同一設定的假星團量出「Hess 摘要與凸出比例」的聯合協方差，使用聯合似然。
3. **在 M45 成功後才拿去 Praesepe。** Praesepe 目前的前向 smoke test 出現 `f_bin=1` 貼邊。先用注入回收檢驗上述方法能否辨識貼邊，不能直接把它當成真實的 100% 聯星率。

## 成本與決策

| 選項 | 成本 | 科學風險 | 建議 |
|---|---|---|---|
| 現在把比例直接加進似然 | 程式改動小 | 高：重複計數，誤差棒不可信 | 不做 |
| 保留為每次前向結果的檢查 | 很低 | 低：不改變後驗 | **現在做這個** |
| 做聯合/排他似然 + 注入回收 | 中等到高 | 可控，但需完整驗證 | 等 M45 的其他系統項先收斂後再排程 |

對高中生版本的重點是：我們不是缺少一個「看起來有用的公式」，而是要先確定它沒有把同一份成績算兩遍。這一次的結果證明模型在凸出星上沒有明顯矛盾；下一次真正值得花算力的工作，是驗證新的統計設計能不能公平地分開聯星比例、伴星質量比與消光。
