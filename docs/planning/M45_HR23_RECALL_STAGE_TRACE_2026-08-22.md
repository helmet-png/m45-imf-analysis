# 外部 M45 成員在哪一關離開？

## 結論先講

在保存的 HR23 高機率成員（P≥0.7）中，沒有任何一顆是因為本專案保存的 `baseline.dat` 成員機率低於 0.7 而離開。已定位出的差異是：

- 433/529（81.9%）進入 `cmd_members.csv`；
- 62/529（11.7%）在 baseline 的本專案機率已通過 0.7，但後來沒有進 CMD；
- 34/529（6.4%）不在保存的 baseline，而且這 34 顆全部是 G≥18；
- 0/529 因 baseline 中的本專案 P<0.7 而離開。

因此，對這份外部高機率快照而言，主要差異不是 pyUPMASK 機率互相衝突，而是較後面的 CMD／測光／星等選擇，以及最暗端沒有出現在保存 baseline。

## 按亮度看

| Gaia G 星等 | 不在 baseline | baseline P<0.7 | P≥0.7 但未進 CMD | 已進 CMD |
|---|---:|---:|---:|---:|
| G < 4 | 0 | 0 | 1 | 0 |
| 4 ≤ G < 5.2 | 0 | 0 | 0 | 0 |
| 5.2 ≤ G < 8 | 0 | 0 | 0 | 15 |
| 8 ≤ G < 12 | 0 | 0 | 2 | 86 |
| 12 ≤ G < 16 | 0 | 0 | 14 | 158 |
| 16 ≤ G < 18 | 0 | 0 | 45 | 174 |
| G ≥ 18 | 34 | 0 | 0 | 0 |

G=16–18 的 219 顆外部高機率成員中，有 45 顆（20.5%）通過 baseline 機率卻未進 CMD。這確認暗端重疊率降低主要發生在成員機率之後。

## 可以說與不能說的事

已驗證：三份保存檔以 Gaia source_id 交叉比對後，上述計數可重現；HR23 P≥0.7 且存在 baseline 的星，其 baseline `probs_final` 全部也至少 0.7。

尚未驗證：這 62 顆分別是被哪一條測光品質規則、顏色條件或星等邊界排除。`baseline.dat` 沒有保存完整 BP/RP flux-over-error 與 excess-factor 欄位，不能僅靠現有中介檔逐條重播品質切割。

阻塞：若要精確分解 62 顆，需要原始 Gaia 查詢表或重新取得這 62 顆的必要測光品質欄位。現在不能把「P≥0.7 但未進 CMD」直接寫成 pipeline 錯殺；兩份目錄的品質政策可能本來就不同。

## 對 IMF 的意義

亮端 G=5.2–8 的 15 顆全部保留，支持目前高質量端在這個可檢查範圍內沒有明顯的外部成員流失。暗端 G≥16 的後續選擇損失較大，低質量 IMF 的完整性說明應把這項亮度依賴列為限制。

這份追蹤不能直接產生完整度修正權重，也不能直接把未進 CMD 的星加回樣本。

